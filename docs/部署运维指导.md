## 1. 部署架构

```
┌──────────────┐   静态资源(HTML/JS/CSS/图标/插件zip)   ┌────────────────────┐
│  用户浏览器    │ <──────────────────────────────────  │ 静态托管 / Nginx     │
│  方子 PWA     │                                       │ (dist/ 全量上传)     │
│              │ ── 可选：POST 反馈 ───────────────▶  │ Serverless 邮件函数  │ → wotongming@163.com
│              │ ── 可选：POST 下单/查单 ──────────▶  │ 支付后端 /api/billing│ → 微信/支付宝/Stripe…
│              │ ── 仅配置后：POST {base}/embeddings  │ 你指定的 Embedding 网关（OpenAI 兼容）
└──────────────┘                                       └────────────────────┘
```

- 前端构建产物 `dist/` 为纯静态文件，可托管在任何静态服务器 / 对象存储 / CDN。
- 默认不依赖任何数据库：工具清单在构建期打进产物，用户的收藏 / 订单 / 用量 / 配置全部在浏览器本机。
- 三个可选外部能力都用**构建期环境变量**开关，未配置即自动退化（反馈本地排队、支付本地模拟、检索纯关键词）。

## 2. 环境要求与本地命令

- **Node.js ≥ 20.19**（vite-plugin-pwa 2.x 要求；建议 22 LTS），npm 10+。
- 依赖均为 MIT / Apache-2.0 等商业友好许可证。

```bash
npm install        # 安装依赖
npm run dev        # 本地开发（http://localhost:5173）
npm run type-check # vue-tsc 严格类型检查
npm test           # 单元测试（node:test + tsx）
npm run verify:tools  # 首页示例提问命中回归（真实搜索引擎，top-1 必须匹配）
npm run build      # 类型检查 + 生产构建 → dist/
npm run preview    # 本地预览 dist/（http://localhost:4173），用于上线前自检
```

**上线前最小验收清单**：`type-check` 0 错误 → `test` 全绿 → `verify:tools` 全绿 → `build` 成功 → `preview` 下抽查首页、搜索、一个付费工具、插件下载页。

## 3. 构建配置与环境变量

环境变量在**构建期**注入（Vite 规则，`VITE_` 前缀），可通过 `.env.production` 或 CI 环境变量提供。仓库提供 `.env.example` 模板。

| 变量 | 必填 | 示例 | 作用 | 未配置时 |
| --- | --- | --- | --- | --- |
| `VITE_BASE` | 否 | `/fangzi/` | 部署子路径（首尾需带 `/`），同时影响 PWA `start_url/scope` 与路由回退 | 根路径 `/` |
| `VITE_FEEDBACK_ENDPOINT` | 否 | `https://api.example.com/fangzi/feedback` | 需求反馈接收地址（服务端负责发邮件） | 反馈写浏览器本机队列，联网配置后补发 |
| `VITE_BILLING_ENDPOINT` | 否 | `https://api.example.com/fangzi/billing` | 真实支付后端 API 基址 | 使用本地模拟支付（下单即到账） |

> 注意：更换这三个端点后必须**重新构建并发布**才生效。`VITE_BASE` 改为子路径后，静态服务器的 SPA 回退与资源路径也要相应调整。

`.env.example`：

```dotenv
# 部署到域名根路径留空或填 /；部署到子路径必须首尾带斜杠，如 /fangzi/
VITE_BASE=/

# 可选：需求反馈 serverless 函数地址（服务端转发邮件到 wotongming@163.com）
# VITE_FEEDBACK_ENDPOINT=https://your-domain/api/fangzi/feedback

# 可选：真实支付后端基址（实现 /checkout、/order/:id）；不配置则为本地模拟支付
# VITE_BILLING_ENDPOINT=https://your-domain/api/fangzi/billing
```

## 4. 静态托管部署

构建后把整个 `dist/` 目录原样上传即可。

### 平台类（Vercel / Netlify / Cloudflare Pages 等）

- 构建命令：`npm run build`；输出目录：`dist`。
- SPA 回退：配置所有未知路径回退到 `/index.html`（多数平台对 SPA 有预设开关；Vercel 加一条 rewrite，Netlify 加 `/* /index.html 200`）。
- 缓存：对带哈希的 `assets/*` 用长缓存（immutable），对 `index.html`、`sw.js`、`manifest.webmanifest` 用 **no-cache**（见第 6 节）。
- 子路径部署：先设 `VITE_BASE=/子路径/` 再构建。

### 对象存储 + CDN（如 OSS/COS/S3 + CDN）

- 开启静态网站托管，默认首页与 404 页都指向 `index.html`。
- CDN 侧按第 5 节规则区分缓存，并确保 `sw.js` 不被强缓存。

## 5. Nginx 配置参考

```nginx
server {
    listen 80;
    server_name fangzi.example.com;
    root /var/www/fangzi/dist;
    index index.html;

    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml application/manifest+json;
    gzip_min_length 1024;

    # 1) Service Worker 与清单：绝不强缓存，保证能即时更新
    location = /sw.js {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        try_files $uri =404;
    }
    location = /manifest.webmanifest {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }

    # 2) 带内容哈希的构建产物：长缓存
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        try_files $uri =404;
    }

    # 3) 插件压缩包：大文件，不强依赖 SW；给中等缓存，由浏览器/CDNS 缓存
    location /plugins/ {
        add_header Cache-Control "public, max-age=86400";
        types { application/zip zip; }
        try_files $uri =404;
    }

    # 4) 应用外壳与其它静态文件
    location / {
        add_header Cache-Control "no-cache";
        try_files $uri $uri/ /index.html;   # 最后一项是 SPA history 路由回退
    }
}
```

子路径部署（`VITE_BASE=/fangzi/`）时，把 `root` 下的路径前缀改为 `/fangzi/`，回退改为 `/fangzi/index.html`。

## 6. PWA / Service Worker 运维要点

- 使用 `vite-plugin-pwa` 的 **generateSW + autoUpdate**：构建时自动生成 `dist/sw.js` 与预缓存清单，发布新版本后客户端自动检测更新并在下次加载时激活。
- **预缓存范围**：`**/*.{js,css,html,svg,png,ico,woff2,json}`，上限 5MB；已显式排除 `plugins/**`（插件 zip 不进预缓存，改由运行时 `StaleWhileRevalidate` 缓存，30 天、最多 20 个）与 `tools-index.json`。
- **更新生效关键**：`sw.js` 与 `index.html` 必须 `no-cache`，否则用户会长期停留在旧版本（这是 PWA 更新不生效最常见原因）。
- 排查缓存问题时，可在浏览器 DevTools → Application → Service Workers 里 `Unregister`，并清空 Storage；应用「设置」页也提供「清空本机数据」。
- 离线能力覆盖应用外壳与已预缓存资源；在线 Embedding、支付、反馈补发本身需要网络。

## 7. 需求反馈服务端（可选）

前端 `src/core/feedback.ts` 行为：

- 未配置 `VITE_FEEDBACK_ENDPOINT`：写入 localStorage 队列（键 `fangzi:feedback-queue`，保留最近 200 条），返回 `queued`，之后可用 `retryQueuedFeedback()` 补发。
- 已配置：`POST <endpoint>`，JSON 请求体如下：

```jsonc
{
  "content": "用户输入的需求正文（1~2000 字）",
  "context": { "query": "触发无结果的搜索词", "ua": "User-Agent", "lang": "zh-CN" },
  "createdAt": "2026-10-14T03:00:00.000Z"
}
```

服务端要求：返回 **2xx** 即视为投递成功；非 2xx 或网络错误，前端会把该条放回本地队列稍后重试（需做幂等去重，建议以 `createdAt+content` 哈希去重）。

服务端职责：**把内容通过邮件发送到固定收件人 `wotongming@163.com`**。可用任意 Serverless 平台的免费额度（Vercel/Netlify Functions、Cloudflare Workers、云函数）+ 邮件服务（如 Reset 名之外的 SMTP / SendGrid / 阿里云邮件推送等，按商用授权选择）。务必：

- 校验 `content` 非空、长度 ≤ 2000；
- 加来源 / 频率限制，防止接口被滥用刷邮件；
- 邮件凭据只保存在服务端环境变量，**绝不能**下发到前端。

最小伪代码：

```js
export default async function handler(req, res) {
  if (req.method !== 'POST') return res.status(405).end();
  const { content, context, createdAt } = req.body || {};
  if (!content || String(content).trim().length > 2000) return res.status(400).end();
  await sendMail({
    to: 'wotongming@163.com',
    subject: '[方子需求反馈] ' + String(content).slice(0, 30),
    text: `${content}\n\n---\n来源搜索: ${context?.query ?? ''}\n时间: ${createdAt}`
  });
  res.status(200).json({ ok: true });
}
```

## 8. 真实支付后端（可选）

前端 `src/core/billing/` 的 `RemoteBillingProvider` 在配置 `VITE_BILLING_ENDPOINT` 后启用，约定两个接口：

### 8.1 下单 `POST <BILLING_ENDPOINT>/checkout`

请求体（对应 `CheckoutRequest`）：

```jsonc
{
  "toolId": "image-converter",
  "kind": "buyout | freemium-pro | usage-pack",
  "amountCents": 2990,        // 金额单位：分
  "currency": "CNY",
  "units": 10                 // 仅 kind=usage-pack 时出现，表示购买的额度单位数
}
```

响应体：

```jsonc
{
  "order": {
    "id": "ord_xxx",
    "toolId": "image-converter",
    "kind": "buyout",
    "amountCents": 2990,
    "currency": "CNY",
    "units": null,
    "status": "pending",       // pending | paid | refunded
    "provider": "wechat",
    "createdAt": "2026-10-14T03:00:00.000Z"
  },
  "payUrl": "https://支付网关收银台地址"   // 存在则前端跳转到收银台
}
```

### 8.2 查单 `GET <BILLING_ENDPOINT>/order/:id`

返回最新 `Order`（支付网关异步回调把 `status` 更新为 `paid`）。前端从收银台返回后轮询此接口同步权益。

### 8.3 接入要点

- **金额以后端为准**：下单时后端应按 `toolId + kind` 重新核算价格，不要信任前端传入的 `amountCents`。
- 支付结果以网关**异步回调（webhook）**写单为准，回调需验签、幂等。
- 权益/额度正式上线应存服务端并按用户账号体系发放；当前前端在未登录阶段用本机存储演示，跨设备同步需配合账号体系。
- 插件类高级功能通过「授权码」方式：站点侧校验权益后颁发，插件在请求中携带授权码，插件不接触任何支付密钥。
- 切换支付后端只需配置环境变量后重新构建，无需改业务代码；三种计费模式（买断 / Freemium / 按次 + 额度包 + 周期重置）的前端判定逻辑已在 `src/core/billing/billing.ts` 实现。

## 9. 数据持久化与隐私边界

| 数据 | 存放位置 | 键 / 库 | 清除方式 |
| --- | --- | --- | --- |
| AI 检索配置 | 浏览器 localStorage | `fangzi:settings:v1` | 设置页清除配置 / 清空本机数据 |
| 收藏工具 | localStorage | `fangzi:favorites:v1` | 取消收藏 / 清空本机数据 |
| 订单、权益、用量 | localStorage | `fangzi:billing:v1` | 清空本机数据 |
| 待发反馈队列 | localStorage | `fangzi:feedback-queue` | 补发成功后自动清理 / 清空本机数据 |
| 工具向量缓存 | IndexedDB | 库 `fangzi-vectors`（按模型隔离、内容哈希去重） | 清空站点数据 |

- 工具处理的**用户内容（文件、图片、文本、密码等）默认不出本机**，服务端无需为其准备存储。
- 因为核心数据在客户端，**静态服务器无需数据库备份**；需要备份的是构建产物、插件 zip、可选的反馈 / 支付服务端数据。

## 10. 新增 / 更新工具上线流程

1. 本地执行 `npm run new:tool -- <id> <web|plugin> "名称"` 生成骨架。
2. 补全 `src/tools/<id>/manifest.ts` 的关键词、场景、痛点、目标用户与计费规则；网页工具实现 `index.vue`，写 `guide.md`。
3. 若要上首页浮动提问，在 `src/core/sample-queries.ts` 增加 `{ text, expectToolId }`。
4. 更新**根 `README.md` 工具清单**（七字段 + 更新时间与 `updatedAt`）。
5. 本地四件套验证：`npm run type-check` → `npm test` → `npm run verify:tools` → `npm run build`，并用 `npm run preview` 抽查。
6. 全量上传新的 `dist/`（静态托管一般为原子发布 / 整目录覆盖）。
7. 发布后确认 `sw.js` 已更新、客户端能自动升级；抽查新工具搜索可命中、详情页「用户指导」可打开。

> 工具清单在构建期固化进产物。新增工具**必须重新构建发布**，不需要改注册表、路由或搜索代码（`import.meta.glob` 自动发现，启动时校验 manifest 合法性，不合法会直接报错拦截发布）。

## 11. 浏览器插件打包发布

当前示例插件源码在 `plugins-src/fangzi-companion/`（Manifest V3）。

```bash
# 打包（在项目根执行，zip 内为扩展文件，不含外层目录）
cd plugins-src/fangzi-companion
zip -r ../../public/plugins/fangzi-companion/fangzi-companion-chrome-<version>.zip .
cd -
# 计算校验值与字节数，回填到 manifest.ts 的 plugins[].sha256 / sizeBytes
shasum -a 256 public/plugins/fangzi-companion/*.zip
stat -f%z public/plugins/fangzi-companion/*.zip   # macOS；Linux 用 stat -c%s
# 完整性自检
unzip -t public/plugins/fangzi-companion/*.zip
```

- 回填 `sha256`、`sizeBytes`、`version`、`minHostVersion` 后，插件工具页会展示并支持「校验 SHA256 后下载」。
- 正式分发可提交 Chrome Web Store / Edge 加载项；企业内网也可沿用「手动加载已解压扩展」方式。上架前以各商店当年的开发者政策与审核要求为准。

## 12. 监控、回滚与故障排查

**监控建议（零成本优先）**

- 静态托管 / CDN 的可用性、`index.html`、`sw.js`、插件 zip 的 200 率与回源命中率。
- 可选服务端：反馈函数调用量 / 错误率、支付下单成功率、webhook 回调成功率与对账差异。
- 前端可接入免费额度内的前端错误上报（自行选型，注意商用授权与隐私合规）。

**回滚**

- 静态发布保留最近若干版本目录（如 `releases/20261014/`），Nginx/平台切换指向即可快速回滚。
- PWA 因有 SW 缓存，回滚版本号要确保新 `sw.js` 一定下发（`no-cache`），客户端才会回到回滚版本。

**常见故障**

| 现象 | 可能原因 / 处理 |
| --- | --- |
| 白屏 / 刷新子路由 404 | 未配 SPA 回退；把所有未知路径回退到 index.html |
| 用户更新后仍是旧版 | `sw.js` 或 `index.html` 被强缓存；改为 no-cache 并重新发布 |
| 搜索一直显示关键词、无混合检索 | 未配置 AI 或 Embedding 不通；设置页测试连接，观察「自动降级」提示 |
| 反馈一直排队 | 未配 `VITE_FEEDBACK_ENDPOINT` 或函数非 2xx；设置页可手动「立即补发」 |
| 点击购买提示模拟支付 | 未配 `VITE_BILLING_ENDPOINT`；配置后重新构建 |
| 插件下载后校验不一致 | zip 损坏 / 被篡改 / manifest 回填值过期；重新下载核对 SHA256 |
| 图片、哈希等工具不可用 | 浏览器过旧不支持 Canvas / WebCrypto / crypto.getRandomValues；更换现代浏览器 |

## 13. 浏览器兼容矩阵

| 能力 | Chrome / Edge | Safari (macOS/iOS) | Firefox |
| --- | --- | --- | --- |
| 基础应用与关键词检索 | 最近两个大版本 ✅ | 最近两个大版本 ✅ | 最近两个大版本 ✅ |
| PWA 安装 / SW 离线 | ✅ | ✅（iOS 需 Safari「添加到主屏幕」） | ✅ |
| IndexedDB 向量缓存 | ✅ | ✅ | ✅ |
| WebCrypto（文件哈希） | ✅ | ✅ | ✅ |
| Canvas 图片转换 | ✅ | ✅ | ✅ |
| 示例浏览器插件 | Chromium 102+ ✅ | ❌（MV3 Chromium 扩展） | ❌ |

主流 Chromium + Safari 覆盖了绝大多数用户；构建目标为 `es2022`，不面向 IE。上线前建议在 Chrome、Edge、Safari 至少各做一次主流程冒烟（搜索 → 打开工具 → 付费墙 → 插件页）。
