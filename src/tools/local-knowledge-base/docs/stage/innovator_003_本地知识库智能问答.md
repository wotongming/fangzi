# 功能建议：数据不出端的本地知识库智能问答（本地 AI · 本地 RAG）

- 序号：003
- 建议形态：网页应用（PWA 内嵌本地知识库 / 独立页面）

## 需求来源

- 隐私敏感文档问答需求已被验证：LocalRAG!（iOS/Android）支持 25 种格式本地检索问答、设备端 AI 完全离线、Claude 模式只发送问题与摘录，明确主打“合同、医疗记录、机密研究资料等敏感文档”场景（来源站点：LocalRAG! 官网，检索关键词：local rag documents on-device privacy；https://localrag.app/zh）
- 开发者社区正在做同类本地 RAG 技能：ModelScope 上的 local-rag 技能用 Qwen2.5+Qwen3-Embedding（OpenVINO INT4/INT8）在本地构建“数据不出机”知识库问答，直击个人笔记、研报摘要、企业文档检索的隐私合规痛点（来源站点：ModelScope，检索关键词：本地私人知识库智能问答 local-rag；https://www.modelscope.cn/skills/ylyhf2026/Knowledge_Base_Intelligent_QA_light）
- 企业端付费验证：WPS AI 企业知识问答基于 RAG 私有化部署，599 元/人/年，主打数据安全合规（来源站点：WPS 365，检索关键词：企业私有知识库 RAG 私有化部署；https://365.wps.cn/content/5cb67f3a961e4df8ad9572c734eceb51.html）；边界智能睿阁同样以“数据不出内网、引用溯源”为卖点做企业知识库（来源站点：边界智能，检索关键词：企业知识库智能体 数据不出内网；https://www.bianjie.ai/reknow）
- 行业趋势：端侧大模型解决“数据不能上传”的合规问题——投行/律所/医院明令禁止把审计底稿、法务材料上传公有云（来源站点：爱范儿《那些想用但不让用 AI 的公司，终于可以用 AI 了》，检索关键词：本地 AI 数据合规 律所 投行；https://www.ifanr.com/1678332）
- 学术综述确认端侧 LLM 应用（个人助手、办公助手、医疗监测）的价值=本地推理响应快+数据不出端+个性化（来源站点：arXiv《A Review on Edge Large Language Models》，检索关键词：edge LLM on-device applications survey；https://arxiv.org/pdf/2410.11845.pdf）

## 使用场景

- **律师/法务**：对合同、判决书、尽调底稿提问，材料涉客户机密，严禁上传云端；需要答案附原文引用可溯源。
- **医生/科研人员**：对病历、指南、论文库提问，数据受个人信息保护法约束，只能本地处理。
- **金融从业者**：研报底稿、客户数据本地问答，数据主权红线。
- **个人知识管理重度用户**：本地笔记、PDF 书库、网课资料库，希望离线语义检索与问答，不信任云端上传。
- **政企/内网办公**：政务、园区、涉密环境无外网，需要开箱即用的离线知识问答。

## 功能描述

- 核心：浏览器内（或本地运行时）运行的本地 RAG 问答系统，文档解析、分块、嵌入、检索、生成全在设备完成，数据不出端。
- 导入：拖入 PDF/Word/TXT/Markdown/CSV/HTML/图片/音频等多格式文档。
- 本地嵌入与索引：本地 embedding 模型（如 Qwen3-Embedding/INT8）构建向量索引，存 IndexedDB/本地存储。
- 检索问答：语义检索（向量+BM25 混合）+ 本地小模型（Qwen2.5 1.5B INT4 级）生成答案，答案附引用片段与相似度分数。
- 溯源：点击引用跳转到原文段落；低置信度明确提示。
- 离线：首次下载模型后完全离线可用。
- 导出：对话记录、问答结果导出；多知识库（集合）管理与权限。

## 目标人群

- 画像：律师/法务、金融从业者、医生/科研、政务办公、知识管理重度用户；隐私敏感型个人用户。
- 规模：全球法律+金融+医疗+科研从业者数千万；个人知识管理用户规模更大且持续增长。
- 付费意愿：强——企业版 RAG 已卖到数百元/人/年（WPS），本地 App（LocalRAG!）提供 1 周试用+订阅；个人付费空间来自“隐私刚需+离线刚需”。

## 建议形态

- 网页应用（PWA）+ 可选本地运行时：浏览器内用 Transformers.js/WebLLM/onnxruntime-web 跑本地 embedding+小模型，PWA 免安装、离线缓存；数据存 IndexedDB。选择网页形态是因为文档就在浏览器/办公环境中，且 PWA 可覆盖桌面与移动端；后续可扩展本地运行时（llama.cpp）提供更强模型。

## 落地价值

- 解决：敏感文档不能上传云端的合规红线；云端问答按 token/席位持续付费；弱网/断网不可用。
- 节省：免云订阅（WPS 599/人/年、睿阁私有化数万起）；律师检索时间从小时级到秒级；数据泄露风险成本。
- 市场空间：本地 RAG 是 2026 年从企业向个人下沉的快速增长需求（企业私有化+个人隐私双驱动）。
- 潜在盈利点：免费基础（文档数与模型档位限制），Pro 订阅解锁多格式/更大模型/跨文档对比/团队共享；企业版内网部署授权。
- **多场景链路**：触发（导入文档）→ 处理（本地解析分块→嵌入→建索引）→ 问答检索（语义检索+生成+溯源）→ 产出（导出/引用定位）→ 后续动作（合规审查、尽调、写作引用、知识归档）；可延伸跨文档对比、报告生成、团队知识库。

## 多场景链路与红海规避判断

- 是否同质化小工具：否（知识库平台型，非单一原子动作）
- 多场景链路：文档导入 → 索引构建 → 检索问答 → 溯源导出 → 知识管理闭环，贯穿法律、医疗、金融、科研、个人知识管理
- 持续使用频次与付费空间：从业者每日高频使用；付费场景=多格式+大模型+团队协作订阅，付费理由=隐私合规刚需+省云费用
- 红海规避：云端 ChatPDF 类红海，但“数据不出端+离线+溯源”细分仍空白；个人级平价本地 RAG 无强势竞品（LocalRAG! 刚起步、偏移动端）
