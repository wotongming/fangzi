## 技术选型与理由

- **Vue 3 + TypeScript + Vite**：与 fangzi 现有技术栈完全一致，经 `import.meta.glob('../tools/*/manifest.ts'|index.vue|guide.md')` 自动发现，新增目录即注册，不改路由表。
- **零新增 npm 依赖**：日期用自写的"本地日历日 + UTC 午夜整数差"引擎，金额用整数分；IndexedDB 直接用原生 API；.ics 手写字符串。无重型依赖、无供应链风险。
- **本地存储 IndexedDB `fangzi-card-billing` v1**：`cards` / `payments` 两表，payments 建 `cardId` 索引；写库前统一 `toPlain()` 深度解除 Vue reactive 代理（复用 shopping-claim 已验证范式），避免结构化克隆 Proxy 报错。
- **商用合规**：全部代码自研，无任何"仅限非商用（NC）"资源；无外部模型 / 字体 / 媒体。

## 关键实现

### 日期引擎（`lib/cycle.ts`，纯函数、可单测）
- `billingDateInMonth`：账单日 31 号在小月用 `clampDay` 落到月末（2 月 28/29）。
- `repaymentDate`：`offset`=账单日+N 天（`addDays` 自动处理大小月、跨年）；`fixed`=固定日号，若该日不晚于账单日则顺延下月。
- `statementBillingForSpend`：消费归入第一个满足条件的账单日；`billingDayConsumptionIntoCurrent` 控制账单日当天计入当期（`>=`）还是下期（`>`，默认，免息更长）。
- `interestFreeDays` = 所在账期还款日 − 消费日。
- 日期差统一走 UTC 午夜整数毫秒 / 86400000 后四舍五入，规避夏令时与本地时区偏移。

### 还款时间线（`lib/timeline.ts`）
- 主事件**始终是当前账期**（最近已出账单的还款日），已还仅置 `paid=true` 并显示"已还/撤销"，不跳到下一期——避免"刚标记还款本期就消失、无法撤销"的体验缺陷（E2E 首跑暴露后修正）。
- 紧急度：`<0` 逾期红、`=0` 今天橙、`<=3` 临近黄、其余绿。

### 计费钩子（`useToolBilling`）
- freemium 主方案：免费层 `FREE_CARD_LIMIT=2`（第 3 张卡 toast 拦截，不进表单）；`canUse('multi'|'picker'|'fee')` 控制不限卡数 / 选卡器 / 年费利息；买断 ¥8.90、订阅 ¥2.6/月、¥26/年（整体偏低，符合低价偏好）。其余分成/按量等模式由统一计费框架具备、配置即可，本次不重复实现。

## 踩坑记录

1. **还款标记后状态丢失**：首版在已还后把时间线切到下一期，导致 E2E 找不到"撤销"按钮。改为主事件锚定本期、仅翻 `paid` 标记后解决。
2. **TS 严格空值**：`split('-').map(Number)` 解构成的元素为 `number|undefined`，`Date.UTC` / 构造器报错；用带默认值的 `??` 取值修复。.ics 提前 3 天日期改用已测的 `addDays`，避免手写 UTC 日期的空值与可读性问题。
3. **测试阈值误判**：单日测把 6 天误断言为 `soon`（引擎阈值是 ≤3 天），修正断言为 `normal`，以引擎口径为准。
4. 沿用既定铁律：数字输入 `v-model` 走 `String` 归一后由 `yuanToCents` 解析；工具内不做 fixed 底栏（外壳 ≤820px 已有底部主导航），功能导航用顶部吸顶 `.seg`。

## 可复用经验

- **纯整数日历日 + UTC 午夜差**：任何"间隔天数/大小月/跨年"类金融、证件、订阅工具都可直接复用 `models.ts` 的 `diffDays/addDays/clampDay`，避免时区/夏令时 bug。
- **时间线"锚定当前账期 + paid 标记"**比"已还即跳下一期"更可撤销、更直观，可复用到所有待办/到期提醒类工具。
- **IndexedDB 写前 `toPlain` 深度解代理**是 Vue3 + IndexedDB 的通用必要步骤，范式已在 shopping-claim / card-billing 两处验证。
- freemium 额度门用"操作入口 toast 拦截、不进入编辑态"实现，既不打断浏览又能明确升级理由。
