## 使用场景

谁：中国城市家庭（25-45岁、已婚有房或租房、有娃上有老），家庭资料的"实际管家"（多为家庭主妇/主夫或其中一方）。

什么时机遇到什么问题：
1. **保修触发**：冰箱/洗衣机/电脑/婴儿车在保修期内坏了，师傅上门前要购物小票、型号、序列号——翻微信支付记录、翻邮箱、翻抽屉，小票热敏纸已褪色，型号在扔掉的纸箱上。
2. **保险理赔触发**：家里被盗/漏水/失火，保险公司要求"损失清单 + 购买凭证 + 发票"，用户现场哭着想不起来三年前买过什么、值多少钱，理赔定损大打折扣。
3. **搬家触发**：几十个纸箱封箱后，过两周想找个订书机/毕业证/充电器，不知道在哪个箱；新家收拾完，老人药瓶、孩子疫苗本又找不到。
4. **年度申报/年审触发**：个税专项附加扣除（大病医疗、住房租金）要留存资料备查；驾照换证、护照到期、车辆年检、医保凭证——一堆到期事项没人统一提醒。
5. **家庭决策触发**：想知道家里这些年在电器上花了多少钱、哪件快过保该续保延保、哪件其实早就该扔——全凭印象。

为什么现有方案不够用：微信/邮箱/相册是分散的"抽屉"，不是档案系统；通用云盘只存文件不理解内容（不知道哪张是保修卡、哪天过保）；纸质票据褪色丢失；Excel 门槛高且没人维护；专门的家庭库存 App 多为海外产品（Itemtopia 等），不贴合国内保修/理赔/个税场景，且要注册上云，敏感证件（身份证、房产证、保单）用户不敢传。

## 功能描述

核心是一个"家庭资产与证件档案库"，拍照入库 + 自动结构化 + 多场景决策支持：

1. **一键拍照入库**：拍发票/保修卡/说明书/证件/保单，本地 OCR 自动提取购买日期、金额、商家、型号、序列号、保修截止日、证件到期日，生成结构化卡片；手动补录也很快。
2. **家庭资产物品档案**：每件贵重/关键物品一张卡（照片 + 类别 + 存放位置 + 购入价 + 凭证附件），支持按"房间/位置"归类；物品之间可挂接"凭证链"（商品卡 ↔ 发票 ↔ 保修卡 ↔ 说明书 ↔ 维修记录）。
3. **到期日历与主动提醒**：保修到期前 30/7 天提醒"可延保/赶紧报修"；证件年审、护照/驾照到期、保险续保、车辆年检、疫苗本等统一到期提醒；避免"过保一天，维修费几千"。
4. **搬家模式**：封箱时给每个纸箱生成 QR 标签（打印贴箱），手机扫码录入箱内物品；搬家后扫码即查"订书机在几号箱"，Keyword 全局搜索秒级定位。
5. **理赔资料包一键导出**：保险出险时，按时间/类别勾选损失物品，一键导出"物品清单 PDF + 每件购买凭证打包 zip"，直接发给保险公司，定损更快更足额。
6. **家庭共享（可选）**：夫妻双人共享同一个家庭档案库，防重复买（这件净化器家里已有）、防找不到（东西在谁那边）。
7. **隐私优先**：默认全部数据存本机 IndexedDB（端到端可选加密），不强制注册、不强制上云；用户可随时导出/删除整个档案库。

## 目标人群

- **画像**：25-45 岁城市家庭实际"大管家"，已婚有房/租房、上有老下有小，家庭年支出 10-40 万，有车险/家财险/医疗险，每年至少搬家或大收拾一次。
- **规模估计**：国内 25-45 岁城镇人口约 3 亿，有家庭资料管理意识的"数字家庭"人群渗透率低但在增长；参考海外 home inventory 品类（Itemtopia、HomeZada、StashDog 等持续有产品和内容产出）与国内保险/保修社区高频抱怨，可触达的目标用户千万级，付费转化人群百万级。
- **付费意愿**：用户为"理赔时少亏几千块、保修内省下维修费、搬家少翻半天"付费理由充分；且涉及敏感证件，对"本地存储 + 无广告"的付费去广告/去容量限制接受度高。

## 建议形态

**本地优先网页应用（可安装为 PWA）**：
- 手机拍照是核心入口，网页/H5 无需下载 App，微信里点开就能用，降低家庭用户（尤其长辈配偶）的使用门槛。
- 敏感证件（身份证、房产证、保单、发票）用户对"上传第三方服务器"天然警惕，本地优先 PWA（IndexedDB 加密 + 可选导出加密备份包）正好消除这个顾虑——这是相对国内通用云盘和海外家庭库存 App 的关键差异化。
- PWA 可离线使用，搬家现场没信号也能扫码录箱。

## 落地价值

- **省时间**：找票据/找物品从"翻半天抽屉"变"搜索 3 秒"；搬家后定位物品从"逐个开箱"变"扫码即查"。
- **省钱**：保修内及时报修避免自费维修（几百到几千元）；理赔时凭证齐全让定损足额（一次理赔差额可能数千到数万）；避免重复购买家里已有的同款物品。
- **多场景链路**：拍照入库（触发）→ OCR 结构化归档（处理）→ 到期提醒/搬家定位/理赔导出包（产出）→ 报修/理赔申报/搬家还原/家庭采购决策（后续动作）。一条数据，反复在保修、理赔、搬家、申报、采购五个高价值场景被调用，不是用一次就走的原子工具。
- **付费空间**：免费档限 50 张档案卡片 + 基础提醒；Pro 订阅（如 12-18 元/年或买断 30 元）解锁无限卡片、OCR 次数、理赔资料包导出、双人家庭共享、加密云备份同步。低频刚需工具的典型付费模型，参考笔记/密码管理器的买断+订阅混合。

## 多场景链路与红海规避判断

- 是否同质化小工具：**否**。单一扫描存档/单一到期提醒是原子小工具；本产品以"家庭资产档案"为中心，串起保修、理赔、搬家、申报、采购五个高价值后续场景，数据一次录入多场景复用。
- 多场景链路：拍照/录物品 → 结构化档案库 →（保修到期提醒 / 搬家 QR 箱单 / 理赔资料包导出 / 申报资料调档 / 家庭防重复采购）→ 具体行动与决策。
- 持续使用频次与付费空间：日常随买随记（高频碎片）+ 保修/搬家/理赔/年审等周期性触发（中频刚需）；Pro 订阅 + 买断混合，敏感品类付费意愿强。
- 红海规避：通用云盘（微信/QQ 邮箱/百度网盘）不懂"内容语义"，只存不提醒；通用记账 App 不管凭证链；国内无专门贴合"保修到期 + 理赔定损 + 搬家定位 + 个税留存"全链路的本地优先产品，海外产品不本土化且要上云。差异化在于"语义化档案 + 本地隐私 + 多场景决策包导出"。

## 强规则核对

| 强规则 | 是否满足 | 依据 |
| --- | --- | --- |
| 给用户带来真实价值（节省时间/资金/情感价值，至少其一） | 是 | 省找物时间（搜索3秒 vs 翻半天）；省钱（保修内报修、理赔足额定损、防重复购买），均有真实来源佐证（Dib、CollectionInventory） |
| 用户有购买意愿（必要条件） | 是 | 目标用户为城市家庭大管家；付费场景为解锁无限档案、OCR、理赔导出包、双人共享、加密备份；付费理由是"理赔少亏几千、保修省维修费"，且对敏感证件隐私付费去顾虑 |
| 形态贴合目标人群使用场景 | 是 | 手机拍照是核心动作，本地优先 PWA 免安装、可离线、隐私可控，贴合家庭用户随手拍、搬家现场无信号、敏感证件不上云的场景 |

> 判定：三条强规则全部满足，产出本建议。
