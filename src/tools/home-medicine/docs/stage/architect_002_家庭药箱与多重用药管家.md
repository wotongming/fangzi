# 架构方案：家庭药箱与多重用药梳理管家

- 对应 pm：pm_002_家庭药箱与多重用药管家.md（结论：可集成·新增）
- 设计日期：2026-10-19

## 需求回顾与设计依据
面向家庭（尤其老人慢病）的药箱、服药计划、临期/成分重复提示与就诊清单。强医疗免责、保守规则。

## 技术方案
### 系统架构
`src/tools/home-medicine/`：index.vue（成员/药箱/计划/梳理/就诊清单视图）→ `lib/` → IndexedDB `fangzi-home-medicine` v1（members/meds/schedules/intakes）。
### 模块设计
- `models.ts`：成员、药品（通用名、类别、处方/OTC/保健、有效期、开封日、开封后可用天数）、服药计划。
- `rules-cn.ts`：**保守**内置规则——常见重复成分（如多种复方感冒药同含对乙酰氨基酚）、少数高风险组合（抗凝+NSAID 等，仅引用公开科普）、剂型开封默认（眼药水 4 周）；每条带"建议咨询医生/药师"与来源；宁少勿错。
- `safety.ts`（纯函数）：对当前在用药集合输出重复成分/高风险/过期/临期/开封过期提示项。
- `schedule.ts`：按早中晚睡前生成当日时间表、漏服处理仅给说明书层面通用提示（不个体化）。
- `store.ts`：IndexedDB + 深度 toRaw；照片复用 `reusable-module/image-redraw` 压缩存证。
- `clinic-list.ts`：导就在用药/保健品全清单（通用名/剂量/频次/起止）文本与图片；`notify.ts` 多级提醒+.ics。
### 关键技术路线
确定性规则 + 日期引擎，无诊断模型；纯前端离线。
### 盈利模式
freemium：单成员/基础计划提醒免费；买断/年度解锁多成员、成分/多药规则、就诊清单导出、加密家庭档案。

## 与 fangzi 现有代码的集成方式
新增目录自动注册；复用 indexeddb-kv、image-redraw、.ics/通知、加密导出范式；不与 pet-health 共用数据（对象不同）；不改核心/SW/manifest。

## 软硬件/依赖选型
现栈 Vue3+TS+Vite；IndexedDB、Web Crypto、Canvas（image-redraw，MIT）、Notification；零新增依赖；无 NC 资源；EdgeOne 免费托管。

## 开发方案
1 人；里程碑：成员/药箱 CRUD 与有效期 → 服药计划提醒 → 安全规则与季度梳理 → 就诊清单与加密导出 → 多端验证。

## 测试方案
单测：有效期/开封倒计时跨月、safety 各规则命中与不命中（避免误报）、时间表生成；vue-tsc 0 错；三视口 E2E（手机优先，老人大字场景）零溢出；verify:tools 回归。

## 实施部署方案
随 main 部署 EdgeOne；规则更新版本化并附来源；回滚=回退提交（增量目录）。

## 风险与反思
医疗合规为最大风险：措辞与边界严格（不诊断不开药、高风险一律引导线下），规则保守可解释。价值真实（老人用药安全、子女安心）。避免复杂化：成员切换与今日用药一屏可达。
