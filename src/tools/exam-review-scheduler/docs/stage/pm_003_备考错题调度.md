# PM 评估报告：在职备考个人错题与弱项调度系统

- 对应 innovator：innovator_003_备考错题调度.md
- 评估日期：2026-10-20
- 结论：**可集成（新增）**

## 与 fangzi 现有功能去重与整合判定

遍历 `src/tools/` 全部 27 个工具，无任何工具面向"学习/备考/错题管理"。最接近的是：
- `local-knowledge-base`（本地知识库问答）：文档语义检索问答，是"读资料"工具，不是"刷题/错题/复习调度"工具。
- `batch-text-processor`：批量文本处理，无学习场景。

**判定：不重复**。本工具是 fangzi 在"教育/备考"赛道的全新方向，新开独立工具 `src/tools/exam-review-scheduler/`。

## 需求真伪判断

真实。广西财政厅 2026-07 高级会计经验分享明确建议"建立错题档案、定期复盘高频失分点"；搜狐 2025-07 指出在职备考常见大坑是"错题不复盘、没有节奏"；腾讯新闻 2025-07 建议"复盘一周错题、攻克薄弱模块"。粉笔/华图/斯尔等机构 APP 的错题本**只收录自家题库里刷的题**，纸质讲义、其他机构网课、PDF 截图的错题全漏在外，且不可迁移。独立的"全来源错题 + 艾宾浩斯调度 + 弱项诊断"工具是利基空白。

## 技术可行性

纯前端可跑通，无后端：
- 错题录入、考点标签、艾宾浩斯复习队列、模考记录全部用 IndexedDB（复用 `reusable-module/indexeddb-kv`）；
- 艾宾浩斯调度算法（1/2/4/7/15 天间隔）：纯 JS 日期计算，无依赖；
- 弱项热力图（按章节/考点聚合正确率与错误频次）：纯 JS 聚合 + CSS 表格色块/SVG 热力图；
- 模考曲线：纯 SVG 折线图（轻量，不引图表库）；
- **拍照 OCR**：作为可选高级功能，首次按需从 hf-mirror 懒加载 ONNX 轻量文字识别模型（Apache-2.0），不打进主包；免费版降级为"文字录入 + 拍照存图附件"。
- 多考试项目（CPA 三科并行）：IndexedDB 按 projectId 分表，纯前端。
- 不依赖云端：所有调度、诊断、曲线本地计算。

## 集成成本与侵入性

低。新开 `src/tools/exam-review-scheduler/` 目录，按 fangzi 工具模板实现；工具注册表追加一项。不改现有工具、不改 Service Worker 全局配置、不改根路由。

## 架构兼容性

完全兼容 Vue3.5 + Pinia + vue-router。无新重型依赖。PWA 离线可用（通勤路上刷复习队列无需网络，这是核心场景）。

## 平台合规评估

- EdgeOne Pages 免费版：纯静态，新增 chunk 约 60–120KB gz，合规。
- 不涉及插件商店、小程序。题目数据用户自录，无版权风险（不搬运题库）。
- 不做"搜答案"功能（避免与机构题库/出版社版权冲突），只做"个人错题调度"，合规边界清晰。

## 资金成本

零资金。纯前端本地实现。OCR 模型用 Apache-2.0 可商用 ONNX 模型，懒加载不进主包。严禁 NC 授权。

## 时间成本与开发难度

预估独立开发者工时：**5–7 个工作日**。拆解：多项目 + 错题 CRUD 1.5d；艾宾浩斯队列 + 今日复习视图 1.5d；考点标签 + 弱项热力图 1.5d；模考记录 + 曲线 + 报考决策看板 1.5d；回归测试 1d。

## 用户真实价值

高。在职考生每天学习 <2 小时，自动调度让稀缺时间花在刀刃上；弱项地图避免"会的反复做、弱的从没碰"。备考期每天打开 1–3 次、连续数月高频，是 fangzi 现有工具中使用周期最长的品类之一，留存与订阅转化强。

## 市场与竞争

背单词 APP（墨墨/不背单词）绑定词库；机构题库 APP 绑定自家题目。本工具打"跨资料、不绑定题库、弱项调度 + 报考决策"差异化，避开正面红海。

## 盈利方式建议

freemium + 订阅，89 元/年 ≈ 890 cents，与 fangzi 档位对齐。免费版：1 个考试项目 + 基础复习队列 + 50 道错题；专业版：多项目并行 + 无限错题 + 拍照 OCR + 弱项诊断报告 + 模考曲线分析 + 报考决策看板。

## 结论与依据

**可集成（新增）**。无重复、纯前端 IndexedDB + 艾宾浩斯算法可跑通、零资金、低侵入、PWA 离线场景正好契合通勤碎片复习。补全 fangzi 在教育/备考赛道的空白。

## 实现规模与无人值守可行性初判

- **档位：M**（多场景链路、IndexedDB 多 store、调度算法、多维聚合；无 WebGPU/无 WASM/无本地大模型权重）。
- 是否依赖大权重：**否**（OCR 可选懒加载）。
- 预估工时：5–7 个工作日。
- 是否适合"一次性端到端做完"：**是**。主流程（录错题→调度→弱项→模考）纯 CRUD + 算法，无外部阻塞，适合无人值守端到端跑完。
