# 部署运维指引：电商商品图批量处理工作台（image-converter「电商上新」模式）

- 对应 architect：`architect_002_电商商品图批量处理工作台.md`
- 编写日期：2026-10-16

## 部署架构与环境准备
纯静态 PWA 的工具内增量，无后端/密钥/新模型。沿用 EdgeOne Pages 现有项目与 MODNet/Real-ESRGAN 自托管模型、现有 Service Worker。

## 软硬件配置清单
无服务器；复用现有构建机。无新增大文件，不增加模型存储。

## 部署步骤
1. 合入 main，EdgeOne Pages 自动构建发布（或控制台手动发布）。
2. 构建守卫确认 dist 无单文件 >25MiB；对比上版总体积仅小幅增加（仅 JS/UI）。
3. 发布后 www 域校验：image-converter 两种模式可切换；通用模式结果与旧版一致（回归）；电商模式可完整出 ZIP。
4. 真机移动端（375）大批量导出抽查。

## 配置项说明
无环境变量。平台规格表在 `ecom/presets.ts`（平台尺寸变更时改此表发版）；计费档位在 image-converter `manifest.billing`（电商上新并入现有买断）。

## 上线/灰度方案
可先发布为“通用处理”默认，电商模式入口可见但标注“新版”，观察大批量失败率/OOM 反馈后再在首页示例提问中主推。回滚：revert 模式切换挂载提交（ecom 为新增文件），通用模式天然不受影响。

## 平台对接指南
- **EdgeOne Pages**：复用现有项目、自定义域与 HTTPS，无新资质；静态资源与现有 AI 模型同站托管。
- 无插件商店分发。

## 运维监控指标与告警
前端本地统计（不上传图片）：各平台规格使用占比、平均张数、目标KB命中率、Worker 失败/OOM 类型，用于调并发与压缩策略。任何处理失败在 UI 给出该文件原因与“重试/跳过”。

## 日志管理 / 备份容灾
无服务端日志/用户图上传；图片与 logo 仅内存与本地下载结果。上新模板为 LocalStorage（清除即重置，属预期），不涉及数据迁移（本次不改任何既有持久数据）。

## 常见故障排查与回滚
- 抠图边缘差：提示在均匀光线下使用或保留原底；MODNet 模型问题参照 image-converter 既有 /mf 排障。
- 目标 KB 达不到：已设质量下限，低于下限给出“无法无损压到该值，已按最佳质量输出”提示。
- 大批量卡顿/OOM：降并发、分批打包；日志中可定位到规格/张数。
- 回滚：单提交移除模式入口；不影响通用模式与其它工具。
