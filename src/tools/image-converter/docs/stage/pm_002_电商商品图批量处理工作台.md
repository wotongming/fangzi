# PM 评估报告：电商商品图批量处理工作台

- 对应 innovator：`innovator_002_电商商品图批量处理工作台.md`
- 评估日期：2026-10-16
- 结论：**可集成（重构升级原功能 image-converter）**

## 与 fangzi 现有功能去重与整合判定
与 **#10 `image-converter`（本地图片AI增强工作台）高度相关**：该工具已具备转换/压缩/裁剪、AI 超分 4x（Real-ESRGAN）、**AI 去背景（MODNet）**、批量工具链与 ZIP 导出、SW 缓存模型。属于「**重复但有明显区别**」：现有工具面向通用图片处理，未覆盖电商卖家“上新”链路的**新痛点/新场景**——多平台规格预设（1:1/3:4、800/1200px、目标 KB）、批量水印（文字/logo 平铺）、批量按规则重命名并按平台分目录、**换底（纯色/自定义底图/留白居中）**、一键上新资料包。

整合方案（重构升级，不新增并列工具）：在 image-converter 内新增「**电商上新**」模式/Tab（复用其入口、目录、关键词、批量管线与 ZIP 能力），新增：①平台规格预设包；②水印模块（Canvas 绘制，无 AI）；③重命名/分目录规则；④基于已有 MODNet alpha 通道的换底合成（纯色/自定义图/居中留白，V1 不做 AI 生成场景图以控制体积）；⑤处理模板保存。**不改动**现有通用转换/超分/去背景入口与逻辑。

存量保护：image-converter 基本为无状态即时处理（无长期用户数据库），主要风险在批量管线的参数结构。必须保持原有工具链 JSON/参数字段向后兼容（新字段可选、缺省回退旧行为），并对存量“去背景/超分/转换”做回归；不覆盖任何已缓存模型 key。

## 需求真伪判断
真需求。Operimage（$49 买断本地批量）、Photomop、Photoroom（高频卖家抱怨导出上限）等印证电商批量上新的高频与付费；中文小卖家/跨境群体庞大。每周/大促高频使用。

## 技术可行性
可纯前端实现（M 档）。规格/水印/重命名/分目录/换底合成均为 Canvas+JSZip+Worker 成熟能力；抠图复用已集成的 MODNet，无需新模型；批量走 Web Worker，WebGPU/WASM 已具备。无新增重型依赖。

## 集成成本与侵入性
集中改 `src/tools/image-converter/`（新增模式与模块），核心框架零改动；不改 SW 策略（无新模型，包体几乎不增）。需保证旧工具链回归通过。侵入性低-中。

## 架构兼容性
完全沿用现有 Vue3/Canvas/Worker/可复用模块，符合零后端与开发规范。

## 平台合规评估
EdgeOne 静态无限制；纯客户端处理。无商店问题。

## 资金成本
零资金，全部依赖现有免费可商用资产（MODNet/Real-ESRGAN 已确认商用友好）。

## 时间成本与开发难度
约 3–5 人日（多为 Canvas/规则工程 + UI + 多端验证）。复杂度 M。

## 用户真实价值
一次上新几十上百张从数小时降到十几分钟，全分辨率不限张数、原图不外泄、省云订阅。显著提升工作类工具付费转化。

## 市场与竞争
Operimage（仅 macOS）、Photomop（偏单张）、云工具（限张/限分辨率/订阅）。差异=本地批量+全分辨率+中文多平台规格/命名/打包一条龙+买断，且在已有工具内增量交付。

## 盈利方式建议
现有 image-converter 计费档位基础上，将「电商上新（批量水印/规格包/换底/上新资料包）」纳入买断专业能力（Freemium+¥49.9 买断），不另立计费项。

## 结论与依据
**可集成（重构升级 image-converter）**：核心 AI 能力已存在，新增的是高价值电商场景工程能力，纯前端、零新增模型/成本、对存量可做到向后兼容；按存量数据/配置保护要求实现并回归。
