# 架构方案：电商商品图批量处理工作台（在 image-converter 内新增「电商上新」模式）

- 对应 innovator：`innovator_002_电商商品图批量处理工作台.md`
- 对应 pm：`pm_002_电商商品图批量处理工作台.md`（结论：可集成-重构升级原功能 image-converter）
- 设计日期：2026-10-16
- 承载工具：现有 **#10 `image-converter`**（不新增并列工具），档位 M

## 需求回顾与设计依据
image-converter 已具备转换/压缩/裁剪、AI 超分、AI 去背景（MODNet）、批量管线与 ZIP。本次按 PM 结论做**增量重构**：在该工具内新增「电商上新」模式，补齐多平台规格预设、换底、水印、批量重命名/分目录、上新资料包；复用其入口、目录、关键词、批量队列与 ZIP，不改动通用模式既有行为，不新增模型。

## 技术方案
### 系统架构（在现有分层内新增模块）
- **模式层**：image-converter 顶部模式切换「通用处理 / 电商上新」（默认通用，URL query 可记忆）。电商模式是一套预设化的批量流水线，复用现有任务队列与 Worker。
- **规格预设模块 `ecom/presets.ts`**：声明式平台规格表（淘宝主图 800/1200 1:1、拼多多、闲鱼、小红书 3:4、抖音、Temu/Shopee、自定义），每条含目标边长、比例策略（contain 留白居中 / cover 裁剪）、格式、目标文件大小（二分质量压缩到 ≤KB）、背景色。
- **画布处理 `ecom/compose.ts`**（OffscreenCanvas，Worker 内）：按规格 resize、留白/裁剪、**换底合成**（已有 MODNet alpha：主体抠出→绘到纯色/渐变/自定义底图→可选等比留白与阴影）、锐化、圆角/边框。
- **水印 `ecom/watermark.ts`**：文字（字体/字号/颜色/透明度/角度/平铺间距）或 logo 图（用户上传，仅内存/本地），九宫格定位与对角/平铺。
- **命名与分包 `ecom/pack.ts`**：模板变量 `{商品名}_{颜色}_{平台}_{序号}`（正则净化非法文件名字符），按平台/规格生成目录树，交由现有 JSZip 打包；导出 manifest.csv（原名→新名、规格、字节）。
- **模板持久化**：上新模板（规格集合+水印+命名规则）存 LocalStorage（`fz-img:ecom-templates`），纯配置、无媒体库。

### 模块设计
在 `src/tools/image-converter/` 下新增：
- `ecom/presets.ts`、`ecom/compose.ts`、`ecom/watermark.ts`、`ecom/pack.ts`、`ecom/types.ts`
- 视图：`components/EcomMode.vue`（规格选择、底图/水印、命名预览、队列、打包），复用现有批量列表/进度/缩略图组件。
- 复用现有 MODNet 调用（输出含 alpha）、超分、压缩与 ZIP、Worker 封装、`worker-post`、`gpu-detect`。

### 关键技术路线
- 纯 Canvas2D/OffscreenCanvas + Worker，无新依赖；AI 抠图仍走已集成 MODNet（Apache-2.0/MIT 系，已确认商用友好），不做 AI 生成场景（控体积/风险）。
- “目标文件大小”用质量二分（WebP/JPEG，40–92）在 Worker 内逼近；PNG 无损则只缩放不承诺 KB。
- 大批量（数百张）采用并发受限队列 + 小步进度，内存及时 transfer/释放，避免移动端 OOM。
- 全分辨率不缩放降级（除非平台规格要求），不加水印到免费成果之外的强制内容。

### 盈利模式
并入 image-converter 现有买断：通用基础功能维持现状，「电商上新（平台规格包/批量水印/换底/上新资料包/模板）」为买断专业能力（Freemium 可免费处理少量带张数上限，买断 ¥49.9 不限量）。不新增独立计费项。

## 与 fangzi 现有代码的集成方式（含存量保护）
- 只在 `src/tools/image-converter/` 内增量：新增 ecom/ 子模块与一个模式视图；在工具主视图加模式切换；README/关键词补充“电商/上新/白底图/水印”。
- **存量兼容硬要求（PM 第5条）**：现有批量管线参数为联合类型，新增字段全部可选并缺省走旧逻辑；不修改通用模式的默认参数、处理顺序、输出命名与 ZIP 结构；不更改已缓存模型 cache key（复用 MODNet，不重拉）。
- 无 IndexedDB 用户媒体库（该工具本就无状态），新增仅 LocalStorage 模板（带 try/catch 与版本号 `v1`，损坏回退默认）。
- 不改 SW/manifest/路由；不新增模型 → 包体几乎不增。

## 软硬件/依赖选型（商用授权）
无新增第三方依赖；沿用现有 MODNet/Real-ESRGAN（商用友好）、JSZip（MIT）、Canvas/Worker 原生能力。全部免费可商用。

## 开发方案
Vue3+TS，1 人，约 3–5 人日。M1 规格预设+换底+压缩到目标大小；M2 水印+命名/分包+ZIP+CSV；M3 模板持久化+多端与大批量压测。

## 测试方案
- 单测：presets 比例/边长/目标大小策略、文件名净化与模板渲染、pack 目录树与 manifest、compose 像素级（用小尺寸固定图断言中心像素/留白尺寸/合成 alpha）。
- E2E：导入混合尺寸图→选多平台规格+水印+换底→ZIP 结构/文件数/尺寸/体积断言；**回归通用模式**（转换/压缩/去背景/超分旧流程行为不变）。
- 大批量：200 张小图压测无崩溃、进度正确；移动端 375/平板 834 无溢出。
- EdgeOne 限额：无新大文件，dist 不显著增加，最大单文件仍 <25MiB。

## 实施部署方案
随主站静态发布；回滚=移除模式入口（ecom 模块为新增文件，回退仅一个提交）。灰度先内部跑规格表，确认各平台最新尺寸再开放。

## 风险与反思
真需要吗——卖家上新高频且现有工具限张/限分辨率，痛点实。会搞复杂吗——通过“模式切换”隔离，不污染通用界面。省时间吗——数小时→十几分钟。风险：平台规格会变动 → 预设表做成易更新的独立配置；换底发丝边缘 → V1 复用 MODNet 默认抠图并提供“保留原底/仅白底”开关，不承诺影视级合成。
