# 技术沉淀：星脉（starvein）

- 对应 dev：`docs/stage/dev_001_星脉.md`
- 日期：2026-10-29
- 档位：**M**

## 技术选型与理由
- 单文件原生 Canvas2D + Web Audio，零图片/音频/字体/wasm，零第三方运行时依赖；包体即一个 JS chunk。
- 复用合集 `audio/synth.ts` 的 `NeonAudio`（五声音阶 `tone`、`explode`、`hit`）与 FocusStage 暂停托管，不重写音频/暂停逻辑。
- 纯函数（星图/节拍/combo/潮汐/评级/快照）全部无 DOM 导出，node:test 毫秒级断言；mount 只负责渲染/输入/音频/快照。

## 关键实现与调参
- **星图生成**：核心(500,1380)→出口(500,120)，先贪心铺一条向上通路（每步更靠近出口且 y 递减），再在距离 <300 的邻近节点补边（度数 ≤4）；生成后立即 `bfsPath` 自检，不可达 seed+101 重生成——**必可达不变量**。
- **难度曲线 stageForRun**：
  - 1 段（1–2 局）：12 节点 / 100 BPM / 窗口 ±180ms / 潮汐 0.55 节点·s⁻¹；
  - 2 段（3–5 局）：20 节点 / 110 BPM / ±150ms / 0.8；
  - 3 段（6+ 局）：28 节点 / 120 BPM / ±120ms / 1.1。
  - 取值依据：100 BPM 新手不赶、±180ms 容错；后期 120 BPM 与 ±120ms 制造卡点张力但不劝退。
- **潮汐**：BFS 深度 ≤ 前沿（节点/秒）即吞未点亮节点；抬手后 1.5s 内 ×1.3 作为"犹豫惩罚"。能量 5 格宽容，允许前期失误 2–3 颗。
- **计分**：节点基础 100，PERFECT +50；combo 每级 ×1.1；收线 ×1.5。评级 S/A/B/C 按点亮率 × PERFECT 率分层。
- **渲染**：加法混合辉光、脉冲环、发光折线、PERFECT 粒子（18 粒/次）；DPR + ResizeObserver 全屏自适应。

## 踩坑记录
- E2E 首版用固定中轴折线拖拽，移动端随机星图的节点不在中轴上，导致零点亮；改为按 `debug.nodeScreen(id)` 沿真实节点坐标画线，三视口稳定点亮 6 节点。
- 进入时若立即 `reset()` 会跳过 intro；E2E 只清存档，让首屏 intro 正常出现。

## 可复用经验
- "生成后立即自检不变量（BFS 通路）"是路线类小游戏可解性的最低成本保障。
- 子游戏一律单文件内核 + 最薄 wrapper，挂载 `window.__<id>` 调试句柄，E2E 即可沿真实坐标驱动、不写死布局。
- 音频/暂停/最高分全部复用合集既有能力，子游戏只新增玩法本身。

## 真机待验
