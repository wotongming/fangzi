## 一、技术选型与理由

| 决策点 | 选型 | 理由与兼容性核查 |
| --- | --- | --- |
| 渲染 | 原生 **Canvas 2D** + DPR 适配 + ResizeObserver | 合集内 orbit-surge 之外的第二款纯 Canvas2D 自绘游戏；不需要 three.js / WebGL2 粒子体系，避免引入重依赖。`package.json` **未新增任何运行时依赖**。 |
| 物理 | 自包含反平方引力 + 软化半径 + 净加速度上限 + 固定时间步 | 弹道游戏物理量小、可完全数值化；引力/推斥/黑洞/收集/碰撞/通关全部下沉为无 DOM 纯函数，供 node:test 直测。 |
| 音频 | 复用合集 `audio/synth.ts` 的 `NeonAudio` 与 `haptic` | 不另建 AudioContext；复用 `ensure()/setMuted()/suspend()/close()/blip()/hit()/explode()/tone()`；首次手势后 `ensure()` 解锁，遵守移动端自动播放策略。 |
| 暂停 / 常亮 / 特效档 | 完全交给宿主 `FocusStage.vue` | 子游戏只 `watch(props.paused)` 停止推进并 `audio.suspend()`；不重复监听 `visibilitychange`，不抢 Wake Lock 与菜单。 |

| 关卡进度 | 独立 localStorage 键 `fangzi:gravity-sling:progress:v1` | 只存 `maxReached` 与 `bestScore`，与自动快照、合集高分库、其它游戏键隔离。 |

## 二、关键实现

### 2.1 目录与职责

```
gpu-games/gravity-sling/
├── gravity-sling.vue                 # 最薄 wrapper：挂 canvas、转发 paused/muted/vibrate/particle、emit score/combo/gameover、卸载清理
├── game/
│   ├── level-design.ts               # 50 关常数、类型、难度模型、确定性种子生成器（无 DOM/音频/渲染）
│   ├── levels.generated.ts            # 离线脚本生成的 LEVELS 与 SOLUTIONS（不手工编辑）
│   └── sling-core.ts                  # 纯物理、预测、combo、渲染、输入、音频、快照、进度、离线求解器、mount/destroy
├── docs/stage/                       # innovator / pm / architect / dev / ops 阶段文档
├── docs/level-evidence.json           # 50 关求解证据：seed、重试次数、角度、力度、步数、角度窗口、净空、天体数、门类型
├── docs/guide_007_太空弹弓.md
├── docs/postmortem_007_太空弹弓.md
└── docs/shots/                       # 三视口真实截图
```

wrapper 只做三件事：`onMounted` 调 `mount(canvas, opts)`、`watch` 宿主 props 转发、`onBeforeUnmount` 调 `destroy()` 并删除全局调试缝。游戏状态、渲染循环、输入、音频、快照全部在内核。

### 2.2 多体引力叠加：不是新改合力模型，而是在既有叠加语义上加固

`sling-core.ts` 的 `gravityAccel` 本来就遍历全部 `gravity/repel/blackhole` 体做矢量叠加：

- 代码依据：`sling-core.ts` 中 `let ax = 0; let ay = 0; for (const b of bodies) { ... ax += sign * ...; ay += sign * ... }`；
- 黑洞质量 `m *= 3`；推斥星 `sign = -1`；
- 本轮没有把它改成另一种合力模型，只在循环结束后增加净加速度上限 `MAX_ACCEL = 15_000`，高密度近场叠加时按比例缩放，防止数值爆炸；
- 预测轨迹、运行时弹道、离线求解器全部复用同一个 `gravityAccel/stepFrame`，不存在第二套会漂移的物理；
- 渲染层引力光晕使用 `lighter` 混合，两颗恒星靠近时交叠区域更亮，玩家可以直观看出合力叠加。

### 2.3 50 关有界饱和难度模型

指数难度不能直接放大物理参数：`1.1^49 ≈ 109` 倍会让后期关失控。本轮公式与旋钮如下：

```text
n = level + 1
rawD = 1.1^(n - 1)
saturation = min(1, rawD / (rawD + 6))
```

`saturation` 随关卡上升但收敛到 1；难度主要驱动组合复杂度、天体数量、门体宽度、发射次数与时限，`GRAVITY_G` 只在已验证舒适带内 ±5% 小幅浮动。

| 旋钮 | 前 4 关教学 | 中段 | 后期 35–50 | 硬约束 |
| --- | --- | --- | --- | --- |
| 阶段 | `tutorial` 0–3 | `rise` 4–17、`hard` 18–34 | `late` 35–49 | 阶段由索引固定，不靠随机 |
| 引力星 | 0–1 | 最多 4 | 最多 4 | 非星尘天体总数 ≤12 |
| 陨石 | 0–2 | 最多 6 | 最多 6 | 走廊直线附近避让 |
| 推斥星 | 0 | 18 关后引入，最多 2 | 最多 2 | 反向力，不做实体碰撞 |
| 黑洞 | 0 | 30 关后引入，最多 2 | 最多 2 | 视界内吞噬 |
| 移动星门 | 无 | 25 关后引入 | 持续出现 | 椭圆轨道 |
| 周期星门 | 无 | 15–24 引入；35 后按奇偶引入 | 与移动门混合 | 周期 6s、开启 4s |
| 星门半径 | 72 世界像素起步 | 逐步收窄 | 收敛到 44 世界像素 | 不再继续缩小 |
| 发射次数 | 不限次 `-1` | 最少 2 发 | 最少 2 发 | 不出现 0 发 |
| 时限 | 不限时 0 | 12 关后引入 | 最少 22s | 不压到无法反应 |
| `gravityScale` | `GRAVITY_G` 附近 | 0.95–1.05 倍 | 0.95–1.05 倍 | 不随指数膨胀 |

### 2.4 确定性生成器与离线求解器

**生成器**：`level-design.ts` 的 `generateLevel(index0, seed, relaxed)` 使用 `mulberry32` 确定性随机数；前 4 关保留已试玩验证的教学布局，后续关按难度模型放置星门、引力星、推斥星、黑洞、陨石与星尘。实体障碍会避开锚点到星门的直线走廊，引力星可贴侧边，保证求解器有可复现的人类可达路径。

**求解器**：`sling-core.ts` 的 `solveLevel` 复用 `createInitialState/stepFrame/gravityAccel`，在发射参数网格上搜索：

- 粗网格：角度 `-130°…-50°`，步长 4°，共 21 个角度；力度 `0.35…1.0`，步长 0.05，共 14 个力度；
- 局部细化：最佳解附近角度 ±5°、步长 1°；力度 ±0.08、步长 0.02；
- 角度窗口：在最佳力度下扫描 ±10°，记录仍能命中的连续角度宽度；
- 求解上限：单关 `maxSteps=1200`，离线脚本单关超时 650ms；
- 离线脚本：`scripts/generate-gravity-sling-levels.mjs`；每关换 seed 重试直到求解器通过，并满足最小角度窗口与门体净空。

**可解性门槛**：

- `MIN_ANGLE_WINDOW_DEG = 4`：最佳解两侧至少保留 4° 可容忍角度窗口，避免单像素针孔；
- `MIN_CLEARANCE = 6` 世界像素：命中点距星门边缘至少保留 6px 安全余量；
- `MAX_BODIES = 12`：非星尘天体总数硬上限，兼顾渲染、预测与碰撞性能。

### 2.7 性能优化与实测帧率

- **预测缓存**：拖拽矢量未变时不重复跑 150 步积分；缓存键为 `关卡 + 拖拽坐标取整 + 力度 + 已流逝时间`。移动星门随时间变化，时间进入新的窗口才重算。
- **高密度粒子降级**：非星尘天体超过 9 个时，命中/爆发粒子数量降到 60%，避免后期关粒子叠加造成掉帧。
- **天体硬上限**：非星尘天体总数 ≤12，超出难度模型也不继续堆数量，而是靠种类、运动、限次与时限提高复杂度。

### 2.9 得分、combo 与展示换算

- 借力 `+60 × 倍率`；星尘 `+100 × 倍率`；命中星门基础 `+300`，限时关追加 `剩余秒数 ×10`，限次关追加 `剩余发数 ×50`。
- `bestCombo` 存储语义仍是历史峰值连续借力次数，无借力存 0；`comboDisplayMult` 只在展示层换算：0/非法/负值 → ×1，`1→×1`、`2→×2`、`4→×4`、`5` 封顶 ×4。旧快照 schema、取值、计分与封顶均不变。

### 2.10 与被参照作品的差异化

参照方向仅取「引力井 / 捕获 / 轨道借力 / combo / 预测线 / 难度爬升」等通用机制：本作输入是**按住拖拽反向拉伸 → 力度 + 角度双自由度 → 实时预测轨迹 → 松手发射**，并非 one-tap 时机释放；名称、美术、音效、关卡、道具与 combo 文案均为原创，不含 Starfling 命名或近似商标元素。

## 三、踩坑记录

1. **指数难度不能直接映射参数**：`1.1^49 ≈ 109`，若直接放大 G、天体数或门体速度，后期关必然失控。改为 `saturation = rawD/(rawD+6)` 饱和收敛，难度主要进入组合复杂度与容差，物理常数保持舒适带。
2. **随机障碍会压死可解走廊**：初版生成器只检查天体之间、天体与锚点/星门的距离，陨石可能落在锚点到星门直线上，求解器找不到路径。补充锚点—星门线段距离约束：实体障碍距走廊 ≥125px，引力星 ≥80px。
3. **粗网格覆盖不足**：初版 15 个角度 ×8 个力度，后期关常漏解；扩到 21 角度 ×14 力度并做局部细化后，50 关才全部通过角度窗口与净空门槛。
4. **求解器必须复用运行时物理**：另写一套简化引力会导致“离线可解、实机打不到”。本轮求解器、预测线、运行时弹道共用 `gravityAccel/stepFrame`，保证所见即所得。
5. **旧快照不能因关卡数变化而清空**：13 关链升级到 50 关链时，迁移函数保留分数、连击、星尘、借力与飞船状态，只钳制关卡号；损坏/不匹配仍回退 null，避免白屏。
6. **选关按钮在手机上必须满足 44px**：初版世界坐标按钮高度在手机缩放后不足 44px；本轮把选关卡片高度与导航按钮高度按世界坐标系放大，E2E 实测手机最小触控高度 45.0px。
7. **不新建顶层工具凑数**：子游戏内嵌在 `mini-games` 内，`verify:tools` 口径仍是 35；本轮没有新建顶层 manifest，也没有改 registry、路由、搜索或 ToolRunnerView。

## 五、可复用经验

1. **合集 GPU 子游戏最薄 wrapper 契约**：props `paused/muted/vibrate/particle`、emit `score/combo/gameover`；暂停/音频挂起交给 FocusStage，内核只响应 `paused`，避免每个游戏重复实现 `visibilitychange` 与 Wake Lock。
2. **物理游戏先把判定做成纯函数**：引力加速度、瞄准向量、力度、预测点列、combo、碰撞、快照校验不碰 DOM，node:test 毫秒级覆盖方向/边界/损坏回退，E2E 只负责手势、面板与续玩链路。
3. **难度曲线必须饱和**：指数公式只用于生成“组合复杂度”，不能直接放大引力/速度/门径；参数要设上下限，后期关靠天体种类、运动状态、容差和资源限制提难度。
4. **可解性要由离线证据背书**：确定性种子 + 独立求解器 + 最小角度窗口/净空门槛，把“我觉得能过”变成单元测试与 JSON 证据；预测、运行时、求解三套代码必须共用同一份物理。
5. **快照独立键 + 严格 chain/version**：升级关卡结构时保留旧档迁移路径；读取前先 `validateSave`，空局面不落盘，胜负/重开即清；不要直接拷贝另一游戏的存档实现与键名。
6. **离线 E2E 顺序不能省**：必须先在线让 SW 接管（`controller` 非空）再断网 reload；新上下文第一次加载就断网会绕过缓存导致误报失败。

## 六、真机待验（本轮无头环境无法覆盖）

- 手机真实触控手感：拖拽摩擦、长按不触发系统选中/滚动、单指连发节奏；WeLink / 微信 / 华为内置 WebView 的 Pointer Events 与音频自动播放策略。
- 低端机帧率：120Hz 固定步、高密度关 12 个天体、150 步预测与粒子爆发在中低端安卓上的掉帧情况；必要时由合集特效档位（`particle=low`）进一步降级粒子数量。
- 真实窄门与动目标手感：4° 角度窗口在小屏触控上是否仍宽松；如真机反馈偏紧，可在不破坏可解证据的前提下微调对应关卡门径或陨石位置。
- 真实横屏/刘海安全区：竖屏为主，若用户旋转屏幕，缩放与居中需在真机复核；本轮 E2E 视口均为竖屏比例。
- 长时间挂机后快照体积与恢复一致性；长时间后台切回的音频 `suspend/ensure` 恢复。
- 50 关逐关人工通关体验：离线求解器证明“存在可到达弹道”，不等同于所有普通玩家都能一次通关；后续可根据试玩反馈微调难度曲线与提示文案。
