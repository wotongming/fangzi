## 技术选型与理由

| 项 | 选型 | 理由 / 授权 |
| --- | --- | --- |
| 渲染 | 原生 DOM/CSS + 少量网格（2048/翻牌/华容道/三消均为离散格，无需 Canvas） | 零依赖、包体最小、触屏与可读性好；无图片素材，表情用系统 Emoji，零版权风险 |
| 框架 | Vue 3 SFC + TypeScript（与方子一致） | 走现有工具自动发现框架（manifest.ts + index.vue），零路由/检索/SW 改动 |
| 持久化 | IndexedDB，复用 `reusable-module/indexeddb-kv` | 单例 `fz-mini-games-v1/kv` 存一份 `{best}`，与其它工具约定一致 |
| 计费 | 复用 `src/core/billing` + `useToolBilling`，manifest 声明 `freemium` | 免费 2048/翻牌，付费华容道/三消；本地 LocalMock 可完整演示，接 `VITE_BILLING_ENDPOINT` 即切真实支付 |
| 新增依赖 | **无**（package.json 未改动） | 全部用标准 Web 能力，商用无限制 |

漏洞/兼容性：未引入任何第三方运行时依赖，无已知 CVE 面；兼容 Chrome/Edge/Firefox/Safari 桌面与移动端。

## 关键实现

- 目录：`src/tools/mini-games/`
  - `manifest.ts`：id=`mini-games`、category=`life`、freemium 价 ¥19.90（1990 分），口语化关键词覆盖小游戏/摸鱼/2048/翻牌/华容道/消消乐。
  - `index.vue`（GameShell）：游戏标签、本局/最高分、重新开始、难度切换、专业版付费墙；`:key="game:diff:nonce"` 保证切游戏/切难度/重开时子组件干净重挂载。
  - `components/Game2048.vue / GameMemory.vue / GameKlotski.vue / GameMatch3.vue`：四款游戏，各自维护局内状态，通过 `@score` / `@gameover` 上报外壳；`defineExpose({reset})` 备用。
  - `lib/2048-core.ts`：棋盘移动/合并纯函数（四方向、每子单步只合并一次、可移动判定、终局）。
  - `lib/match3-core.ts`：三消纯函数（初始无三连生成、相邻判定、交换、横纵标记、消除-下落-补充、连锁加权）。
  - `lib/storage.ts`：`loadState/saveBest/persistState`，1.5s 防抖 + 卸载前补写，IndexedDB 失败静默降级内存。
- 2048 输入：键盘（方向键/WASD）、屏幕方向键、触摸滑动（阈值 24px，`touch-action:none`）。
- 华容道初始局面由「已解局面执行数百次随机合法步」生成，**数学上保证可还原**，不会出现无解死局。
- 三消交换前先用克隆棋盘预判是否成三连，非法交换不改盘并提示；无可走步时自动 `createGrid` 洗牌。
- 变现钩子（接好一个主方案）：`billing.isOwned('freemium-pro'||'buyout')` 判定，锁定游戏渲染付费墙，`billing.buy('freemium-pro')` 走统一下单；订阅/用量/分成等其余模式属框架已具备能力，本工具不额外配置。

## 踩坑记录

1. **freemium 权限判定要按 feature 归属**：未传 featureKey 时 `canUse()` 默认放行，因此外壳没有用 feature 粒度，而是用 `isOwned('freemium-pro'||'buyout')` 明确判定「是否已拥有专业版」来决定锁定游戏，避免误放行。
2. **切难度/重开必须重建游戏组件**：初版仅改响应式数组，翻牌计时器与三消 busy 锁可能跨局残留；改为在动态组件 `:key` 中带上 nonce/难度，配合 `onBeforeUnmount` 清理 `setInterval`，每局都是全新生命周期。
3. **`noUncheckedIndexedAccess` 下数组下标可能 undefined**：三消模板里 `grid[r-1][c-1]` 直接下标类型报错，收敛为 `cellVal()` 访问器兜底；`GAMES[0]` 改为 `find(id==='2048')!`。
4. **三消「无解」处理**：8×8 随机盘偶尔会进入无有效交换局面，加了 `hasPossibleMove` 全表探测并自动洗牌，避免卡死。
5. **华容道可解性**：随机乱序排列有约一半概率不可解；改为从已解态做随机合法滑动，保证必有解且不回到已解。

### 物理参数（固定步长 + 子步，堆叠稳定不狂弹不穿模）

- 固定步长 1000/60 ms，每固定步 `Engine.update` 拆成 ×2 子步抑制高速小球穿透；`positionIterations=10`、`velocityIterations=8`。
- 刚体：`restitution=0.22`（不狂弹）、`friction=0.12`、`frictionAir=0.016`、`density=0.0014`；墙体 `friction=0.1/restitution=0.1`。
- 合并判定：**仅同级 + 相对速度 < 5 px/帧**才合并（高速撞击不误触发）；相切/微渗透容差 1.06 倍半径和；接触点生成上一级新球并带 pop 弹动、粒子辉光、轻微震屏与 `navigator.vibrate`；900ms 内连续合成计连锁连击并按 ×1.3 递增加分。
- 越顶死亡线：球体越过红色警戒线**持续 1750ms** 才判负（瞬时擦过清零），过半（875ms）开始闪烁警告 + 提示音。
- 投放：冷却 380ms、下落占用中不可再投；顶部滑轨瞄准 + 半透明引导线。

### 触屏不遮挡方案（手机重点）

- 待投球固定在**顶部安全区窄滑轨**（`env(safe-area-inset-top)` 避让），随水平 X 移动；半透明垂直引导线从滑轨向下标出落点列。
- 手指可在顶部横条或屏幕任意处水平拖动改瞄准 X，但**预览/引导线永远停在顶部安全区**，落点列在触点 y 之上可见，手指不压堆叠区、不遮落点。
- PC：鼠标横向移动瞄准、点击/空格投放，键盘左右方向键微调。

### 2026-10-20 第三轮迭代（删预告胶囊 / 重力感应 / 修斜碰首撞不合）

**① 删除「下一个」预告胶囊 + 全宽贴边投放**：整块 `.mp-next` 胶囊（label「下一个」+ mini 球 + nextName）从模板/状态移除，投出后直接 `rollSpawnTier()` 生成当前球，不再维护 next 队列；旧 `planAimRange/Rect2/rectsOverlap/AIM_HUD_GAP` 及 7 例避让单测全部删除。瞄准纯函数改为 `wallAimRange(width,radius,edge)`：球心只受「半径+极小边距」约束，`[r+edge, width-r-edge]`，左右都能贴墙，**HUD 不缩减可投范围**。左上分数来自宿主 FocusStage `.hud-left`，最左贴边可能与其视觉重叠，改由 `styleHostHud()` 把它压成 22px 半透明圆角衬底胶囊并 `z-index:30` 浮于待投球上层保证可读，`restoreHostHud()` 卸载还原——而不是限制投放。

**② 重力感应（gamma → world.gravity.x）**：
- 纯函数 `gammaToGravityX(gamma,{deadzoneDeg=5,maxTilt=0.6,fullDeg=30})`：死区 ±5° 内归 0，30° 满偏线性映射到 ±0.6（×gravity.y），超幅 clamp，NaN 回退 0；`lerpGravityX(current,target,alpha=0.12)` 指数平滑禁止重力跳变。常量 `GRAVITY_DEADZONE_DEG=5 / GRAVITY_MAX_TILT=0.6 / GRAVITY_FULL_DEG=30 / GRAVITY_LERP_ALPHA=0.12`。
- iOS 13+ `DeviceOrientationEvent.requestPermission()` 必须在用户手势内：非 iOS 直接挂 `deviceorientation`；iOS 先显示「重力感应」按钮，点击在手势内请求权限，granted 才启用，denied/不支持/非 HTTPS **静默回退垂直重力**，游戏全程可玩不卡；右上角开关可关。
- PC 无传感器：瞄准仍由鼠标移动 / `←/→` 负责，倾斜用 `A/D`（或 `Q/E`），同样走死区→映射→clamp→lerp。
- 摩擦调活以便横向重力下真的滚动、回正停住：`BALL_FRICTION=0.14`、`GROUND_FRICTION=0.22`、`FRICTION_AIR=0.035`（球体无滚动阻力，靠空气阻尼耗散惯性），`gravity.y=1` 不变，死亡线规则不动。

**③ 修「同级斜向/切向首撞有时不合」（实锤根因）**：
- 旧判定（已删除的 `scanMerges`）对每对同级球先算整体相对速度 `rvx=a.vel.x-b.vel.x; rvy=...`，再 `if (Math.hypot(rvx,rvy) > MERGE_MAX_SPEED=5) continue`——这个**整体相对速度标量门槛**把斜向/切向擦碰（切向速度大、法向接近小）挡在合并外；且只按距离 ≤(ra+rb)*1.06 轮询，首帧配对跳过或擦碰后保持贴合不再触发 `collisionStart`，表现为「第一次撞不合、弹开再撞才合」。
- 修法：`contactsForMerge(a,b,now,graceMs)` 只看**同级 + 过保护期 `SPAWN_GRACE_MS=260ms` + 相切 1.08 倍**，**完全不看速度**，切向滑动绝不阻止合并；`planMerges(nodes,now,graceMs)` 做本帧去重（一个 body 只合一对、取先到）、新合成球延迟到循环结束再生成避免本帧二次合并（连锁靠后续自然碰撞）、不同级永不合、保护期新球不误合。组件收集 planMerges 结果后统一移除旧球/计分连击（×1.3、900ms 窗口不变）/粒子，循环后在接触点 spawn 高一级球并上弹。

## 可复用经验

- **离散格小游戏无需 Canvas**：2048/翻牌/华容道/三消用 CSS Grid + 状态数组即可，天然响应式、可访问、易测试；只有连续渲染/粒子才需要 rAF+Canvas。
- **纯逻辑内核与渲染分离**：把移动、合并、匹配、结算写成无 DOM 纯函数并注入 `rng`，毫秒级单测即可覆盖易错规则（如「每子单步只合并一次」「连锁加权」），不必等浏览器。
- **可解局面从已解态随机合法步生成**，比随机排列+逆序数判定更简单稳妥。
- **工具级 freemium** 用 `useToolBilling().isOwned('freemium-pro')` + manifest.features 表达即可，无需为每个游戏写支付链路。
