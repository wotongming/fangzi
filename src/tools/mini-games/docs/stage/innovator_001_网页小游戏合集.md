# 功能建议：轻量网页小游戏合集（打发碎片化时间）

- 序号：001
- 建议形态：PWA 内嵌网页小游戏（作为方子单点工具集合中的一个工具）

## 使用场景

- **谁**：方子现有用户中的上班族、学生、通勤人群及家庭用户。
- **什么时机/情境**：通勤、排队、午休、会议间隙等 3–10 分钟的碎片时间，想找一点「稍微动点脑子、难度适中、不要太难」的轻娱乐，而不是刷短视频（易沉浸、内容杂）。
- **遇到什么问题**：碎片时间无聊没事做；现有的娱乐 App 要么重（下载/注册/广告），要么容易让人停不下来。
- **为什么现有方案不够用**：方子目前是纯效率/合规工具集合，没有娱乐类轻量功能；用户希望在自己常用的轻量工具里「顺手玩一局」，不想再装一个大游戏 App。

## 功能描述

- 在方子内新增一个「小游戏」工具入口，内置一批**轻量、难度适中**的网页小游戏（首批建议：2048、翻牌配对、华容道/拼图、数字消消乐、数独等纯前端益智类）。
- 核心交互：进入工具 → 选择游戏 → 开玩（Canvas 即时渲染、纯本地运行、无加载等待）→ 计分/计时/重开 → 最高分与进度本地保存（IndexedDB），下次回来接着玩。
- 可收藏到方子首页、可离线游玩（PWA 预缓存）。
- 后续可持续扩充游戏库（「不断开发一些网页游戏」）。

## 目标人群

- **人群画像**：方子既有用户（生活/工作/合规工具用户），年龄段以 18–45 岁为主；碎片时间娱乐需求普遍。
- **规模估计**：不单独获客，作为方子存量用户的留存/活跃增强功能；方子为工具集合，娱乐功能可拉高回访频次。
- **付费意愿**：对「无广告 + 完整游戏库」的轻量娱乐存在 Freemium 付费空间（需 PM 阶段重点验证；必要条件）。

## 建议形态

选择 **PWA 内嵌工具**（而非独立 App / 小程序 / 浏览器插件）的理由：

1. 与方子现有「单点工具 + 搜索直达」形态完全一致，一个工具一个痛点，用户口语化搜索「小游戏/打发时间/摸鱼」即可直达；
2. 纯前端 Canvas 即可实现，符合方子无自研后端、静态托管 EdgeOne Pages 的架构约束，零新增服务与成本；
3. 新增工具目录 + manifest 即可接入，零核心改动、零路由改动，符合方子强可扩展工具框架。

## 落地价值

- **解决什么问题**：碎片时间无聊；给方子增加「情绪/娱乐价值」维度。
- **节省/收益**：相对大游戏 App，零安装零广告、打开即玩；相对短视频，单局时间可控、不易沉迷。
- **市场空间**：碎片娱乐需求长期存在；作为工具集合的附属功能，不追求独立变现，目标是留存与活跃。
- **潜在盈利点**：Freemium——免费玩基础款；会员解锁完整游戏库 / 去除广告 / 解锁主题皮肤。
- **多场景链路**：触发（碎片时间无聊）→ 搜索/收藏直达 → 玩一局（3–10 分钟）→ 得分/最高分/进度 → 下次回访（留存循环）→ 会员付费解锁（变现环节）。链路完整、可持续。

## 多场景链路与红海规避判断

- 是否同质化小工具：**否**。不是单一原子动作、用完即走；是可持续扩充的娱乐内容集合（多款游戏、不断迭代），具备内容矩阵与留存属性。
- 多场景链路：如上「触发→处理→产出→后续动作」，完整贯穿。
- 持续使用频次与付费空间：碎片时间高频（每天多次）；付费场景=完整游戏库/去广告/会员，理由=用户已表达持续想要更多游戏。
- 红海规避：单机小游戏整体是红海，但本建议**不把游戏当作独立获客产品**，而是方子工具集合中的增量功能，差异化在「随搜随玩 + 离线轻量 + 无广告 + 与效率工具同处一个 PWA」，竞争定位错开。

| 强规则 | 是否满足 | 依据 |
| --- | --- | --- |
| 给用户带来真实价值（节省时间/资金/情感价值，至少其一） | 是 | 提供精神/情感价值（放松、轻娱乐、难度适中的成就感）；相对刷短视频更省时间、可控 |
