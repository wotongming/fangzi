# 部署运维指引：炫酷全屏沉浸小游戏（WebGPU 炫光游戏系列）

- 对应 architect：architect_007_炫酷全屏沉浸小游戏.md
- 编写日期：2026-10-19
- 部署形态：纯静态 PWA，腾讯云 EdgeOne Pages（随仓库 main 分支自动构建发布）；无服务端、无环境变量、无外部 API/对象存储依赖。

## 部署架构与环境准备

- 架构：静态资源（HTML/JS/CSS，引擎/WGSL 以 JS 字符串内嵌、音画程序化、无素材文件）→ EdgeOne Pages CDN → 用户浏览器；GPU 计算与音频全部在客户端本地完成。
- 运行链路不依赖任何自建后端或第三方图形/音频服务；不发起跨域资源请求（无 CDN 模型/字体/音频），因此无 CORS/外联稳定性风险。
- 环境：仓库 `git@gitcode.com:m0_45688211/fangzi.git`，main 分支推送即触发 EdgeOne Pages 构建（现有流水线，无需新增）。

## 软硬件配置清单

- 客户端：支持 WebGPU 的现代浏览器（Chrome/Edge/Firefox/Safari 较新版本）为最佳；不支持时自动降级 WebGL2/Canvas2D。
- GPU/显存：无硬性要求；按设备能力动态分配粒子规模（WebGPU 数千–2 万、WebGL2 千级、Canvas2D 百级），集成显卡/移动 GPU 可流畅运行中低档。
- 服务端：无（静态托管免费额度内）。

## 部署步骤

1. 在本地按 dev 文档完成里程碑并通过质量门：`npx vue-tsc --noEmit`、`npm test`、`npm run verify:tools`、`npm run build`，以及三视口 E2E 与离线加载验证。
2. 构建产物检查：`dist/` 下新增的 GPU 引擎/游戏 chunk 为自动分包的 `.js`，**单文件须 <5 MiB**（workbox 预缓存阈值）且 <25 MiB（EdgeOne 单文件上限）；自研引擎预计远小于该值。
3. git 显式路径 `git add src/tools/mini-games test/mini-games-neon.test.ts scripts/e2e-mini-games-neon-*.mjs README.md`（仅列本功能路径，不带入历史遗留改动），提交信息注明「mini-games 炫光 GPU 系列 Mx（2026-10-19）」，`git push origin main`。
4. EdgeOne Pages 监听 main 自动构建发布；推送后到平台构建记录确认成功，并在 https://www.fangzi.asia/#/t/mini-games 线上回归：选游戏→专注全屏→（支持机）系统全屏→退出恢复。
5. Service Worker `registerType:'autoUpdate'` + `skipWaiting/clientsClaim`，新版本对已打开用户自动接管；如遇缓存异常，提示用户关闭重开一次。

## 配置项说明

- 无构建期密钥/环境变量；`VITE_BASE` 仅在子路径部署时设置（现网根路径无需）。
- 功能内可配项均为**客户端本地设置**（不入库到服务端）：静音、振动、粒子规格（自动/高/低）、色盲模式、防息屏 WakeLock（默认关）；存 IndexedDB `fz-mini-games-v1` 的可选 `settings` 字段。
- 计费：沿用平台统一 billing 与既有 `mini-games` freemium 主价格（不改 `priceCents`）；新增权益通过 `manifest.billing.features` 的 key（如 `neon-library`）声明，`useToolBilling.canUse` 判权，无独立支付配置。

## 上线/灰度方案

- **按设备能力天然灰度**：M1 先发布，所有设备走 WebGL2/Canvas2D（风险最低、视觉已达炫酷）；M2 发布 WebGPU 后端后，仅在 `detectGpu` 确认支持且设备创建成功的浏览器启用 WebGPU，其余保持 WebGL2，无需服务端开关。
- 里程碑各自独立可上线、可回滚；M1 必须先全绿再上 M2，避免一次引入全部风险。
- 建议发布节奏：工作日白天上线便于观察；M2（WebGPU）上线后当天用 1 台安卓 Chrome 与 1 台桌面 Chrome 真机肉眼复核上屏与全屏。

## 平台对接指南

- **EdgeOne Pages**（唯一对接平台）：
  - 控制台入口：腾讯云 EdgeOne → Pages（现有项目，已绑定 GitCode 仓库与 main 分支），无需新建项目或额外资质。
  - 构建配置沿用现状（静态站点、Node 构建、产物目录 `dist`）；本功能不改变构建命令与输出目录。
  - 免费版限额核对（每次发布实测）：单项目存储 ≤5 GiB、文件数 ≤20000、单文件 ≤25 MiB；本功能仅新增小型 JS chunk，无大资产。
  - HTTPS/缓存：沿用平台默认 CDN 与 HTTPS（Fullscreen/WebGPU/Web Audio 均要求安全上下文，现网已满足）；hashed 资源长缓存、`index.html` 与 SW 控制更新，无需额外配置。
- 不涉及 Chrome Web Store / VS Code / JetBrains 等插件商店（PWA 内功能，不分发插件包）。

## 运维监控指标与告警

- 无服务端指标；以**端上可观测（本地、隐私友好）**为主：可在 localStorage 记录命中后端（webgpu/webgl2/canvas2d）、降级原因、设置项，用于用户反馈时自查（默认不上报；如未来要上报须另行告知并匿名化）。
- 发布后重点人工观察：真机 WebGPU 是否命中、移动端帧率/发热反馈、全屏进退是否正常、低端机是否顺畅降级。
- 线上问题反馈渠道：站内反馈邮件（引导系统邮件，收件人 fangziasia@163.com）。

## 日志管理

- 纯前端无集中日志；降级/异常在控制台以统一前缀（如 `[neon]`）输出，便于真机远程调试时截图；生产环境不打印大对象、不采集用户内容。

## 备份与容灾

- 用户数据（最高分/设置）仅在本机 IndexedDB，无服务端副本；专业版可沿用平台既有购买记录恢复权益，但本地分数不随账号漫游（与现状一致，文档中说明清理浏览器数据会丢失）。
- 代码与发布历史由 GitCode 与 EdgeOne 构建历史保留，可随时重新部署任意版本。

## 常见故障排查与回滚预案

| 现象 | 可能原因 | 处置/回滚 |
| --- | --- | --- |
| 进入游戏白屏/黑屏无画面 | device 创建失败未正确降级、canvas 尺寸为 0 | 确认降级链 catch 与 use-lazy-init 在容器就绪后初始化；紧急时回滚到上一版本（revert 提交） |
| 高端机仍走 WebGL2 | requestAdapter 超时/被禁、WebGPU 标志关闭 | 属预期安全降级；检查浏览器版本与 `navigator.gpu`；不影响可玩性 |
| 无头截图全空 | 在软渲染上截 WebGPU 上屏（环境限制） | 视觉验证一律强制 WebGL2；WebGPU 正确性用 compute 缓冲读回，勿反复改渲染器 |
| 手机发热/掉电快 | 粒子/DPR 过高、后台仍在渲染 | 自适应降档；`visibilitychange` 停 RAF；WakeLock 默认关 |
| 退不出全屏/外壳不恢复 | 未成对 exit、Esc 联动缺失 | 路由离开/卸载强制 dispose+exit；系统 fullscreenchange 已在 useImmersive 内联动 |
| 断网打不开 GPU 游戏 | 动态 chunk 未被 SW 缓存（>5MB 或被 ignore） | 确保 chunk 单文件 <5MiB 命中 globPatterns；E2E 覆盖离线加载 |
| 老用户最高分丢失/报错 | storage 结构被破坏 | 本方案不改库名/version/best 结构，settings 可选回退；若出现立即回滚并恢复兼容读取 |
| 音频不响 | 未在用户手势内创建/被系统静音 | 首次点击后 resume AudioContext；遵循静音开关；静默失败不影响游戏 |

- **快速撤回**：本功能为增量、不改 SW/manifest/注册与存量数据，出问题直接在 GitCode `git revert` 对应里程碑提交并推送，EdgeOne 重新发布即恢复；旧版不引用新 chunk，SW `cleanupOutdatedCaches` 自动清理，用户本地最高分不受影响。
