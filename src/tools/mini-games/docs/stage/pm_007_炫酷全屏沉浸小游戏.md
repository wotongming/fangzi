# PM 评估报告：炫酷全屏沉浸小游戏（WebGPU 炫光游戏系列）

- 对应 innovator：innovator_007_炫酷全屏沉浸小游戏.md
- 评估日期：2026-10-19
- 结论：**可集成（重构升级原功能）**——不新增并列工具，在现有工具 `mini-games`（小游戏合集）内新增 GPU「炫光」游戏系列，并把合集升级为「选游戏页 → 游戏内纯净全屏专注态」两层结构。

## 与 fangzi 现有功能去重与整合判定

**对照对象**：现有工具 `src/tools/mini-games/`（manifest id `mini-games`，2026-10-17 上线），首批 4 款——2048、记忆翻牌、数字华容道、三消，**纯 DOM/CSS 渲染、无图片素材、零依赖**；`manifest.immersive=true`（外壳级沉浸开关已打开）；最高分存 IndexedDB `fz-mini-games-v1`。

- **是否重复：大品类重复（都是"小游戏"），但存在明显区别，且区别正是用户新需求的核心。** 逐条比对：

| 维度 | 现有 mini-games | 本次需求（innovator_007） | 是否新增点 |
| --- | --- | --- | --- |
| 渲染技术 | 纯 DOM/CSS 色块，无渲染管线 | WebGPU/WGSL 优先，WebGL2/Canvas2D 降级；GPU 粒子、Bloom 辉光、光影、屏幕震动 | **全新能力** |
| 视觉/手感 | 朴素、安静 | 霓虹、粒子爆炸、拖尾、音频反应、连击变色、振动 | **全新体验** |
| 音效 | 无 | Web Audio 程序化合成、节奏玩法 | **全新能力** |
| 全屏沉浸 | 仅"外壳级"：隐藏应用顶栏/底部 Tab；**游戏区内仍常驻说明文案、4 个游戏切换 Tab、本局/最高分栏、重开按钮** | **"游戏内专注态"：进入后画布铺满安全区，游戏进行中不显示任何与当前操作无关的信息，HUD 极简且自动隐去，仅暂停/结算才出菜单** | **明显升级（用户最强调）** |
| 玩法 | 4 款经典益智 | 炫光连消 / 霓虹脉冲（节奏）/ 星轨穿梭 3 款实时表现型 | 新增玩法 |

- **判定结论：重复但有明显区别**。新需求提出了现有功能未覆盖的两个真实缺口——**GPU 级炫酷实时表现**与**游戏进行中的绝对纯净全屏**。因此**不单独新开一个并列游戏工具**（会与 mini-games 抢入口、分散"小游戏"关键词与用户认知），而是**重构升级 `mini-games`**：
  1. 在合集内新增「炫光 / NEON」分区承载 GPU 游戏，复用同一入口、目录、搜索关键词与计费；
  2. 抽象统一的「游戏内专注全屏容器（FocusStage）」，**新旧游戏全部纳入**——新 GPU 游戏满屏渲染，现有 4 款 DOM 游戏在同一容器内居中限宽纯净呈现（玩法与外观不变）；
  3. 炫光连消的玩法判定**复用现有 `lib/match3-core.ts` 纯逻辑内核**（createGrid/swap/findMatches/resolve），只替换渲染与表现层，避免重复造轮子。

### 存量数据与配置保护（硬性约束，必须满足）

- **现有数据结构**：IndexedDB 库 `fz-mini-games-v1`（v1），单例文档 `{ id:'state', best: Record<string, number> }`，键为 `${gameId}:${difficulty}`，经 `reusable-module/indexeddb-kv` 读写；另有运行期设置（本次会新增静音/振动/粒子规格等）。
- **兼容/迁移方案（零迁移、不丢存量）**：
  - **不改库名、不升 version、不改 `best` 结构**；新 GPU 游戏只用**新的 gameId 键**（如 `glow-match:classic`、`neon-pulse:normal`、`orbit-surge:classic`），与旧键 `2048:*`/`memory:*`/`klotski:*`/`match3:*` 互不冲突；旧用户打开后历史最高分原样显示。
  - 新增设置项（静音、振动、粒子规格、色盲模式）独立存于同一 state 文档的**可选新字段**（如 `settings?`），读取时 `?? 默认值` 回退；旧文档没有该字段不报错。写库沿用 `persistState`/防抖，保持单文档极小。
  - 现有 4 款游戏组件与其 props（`difficulty`、`score`/`gameover` 事件）契约不变，只把外层容器换成 FocusStage，不侵入游戏内部逻辑。
  - **验证点**：升级后构造含旧 `best` 的库，断言旧分数仍在、新键可追加、无 `settings` 时回退默认；若任一方案要求改动旧数据结构，则放弃该方案、保持现状。
- 结论：可与存量数据/配置安全共存，允许按"重构升级原功能"实施。

## 需求真伪判断

- **真痛点，且来自用户主动、明确、重复强调**：用户原话两次强调"沉浸感/全屏""与游戏无关的信息一定不要展示""白占空间"，说明现有合集"能玩但不够爽、画面不够炫、游戏时干扰项多"已被实际感知。
- **技术时机成熟**：WebGPU 2025 年已在 Chrome/Edge/Firefox/Safari 全量可用，移动端可高帧率；不做将长期落后于网页游戏画质基线。
- **使用频次**：碎片时间高频（通勤/排队/午休），属于高回访、单次时长短的典型留存型场景。
- **与平台用户匹配**：mini-games 已是现有工具，升级直接服务存量用户并强化拉新话题性，无人群错配。
- 风险：玩法本身非原创、易被模仿；但本需求价值在"工程克制下的顶级画质 + 绝对纯净体验 + 零下载离线"，真伪成立。

## 技术可行性（围绕 fangzi 现有技术栈，纯前端）

- 全部能力均为浏览器原生、无需后端：**WebGPU/WGSL**（粒子 compute、instancing、多通道 Bloom）、**WebGL2**（FBO 辉光、粒子降级）、**Canvas2D**（最终兜底，`globalCompositeOperation='lighter'` 模拟发光）、**Web Audio API**（程序化音效/节拍）、**Fullscreen API**（`useImmersive` 已封装）、**navigator.vibrate**（触感，可关）、**requestAnimationFrame + DPR/帧率自适应**。
- 直接复用现有资产：`reusable-module/gpu-detect`（只探 adapter、不提前 destroy device）、`reusable-module/use-lazy-init`（canvas 在容器/全屏就绪后再初始化）、`src/tools/mini-games/lib/match3-core.ts`（连消判定内核）、`indexeddb-kv`（分数/设置）、`useToolBilling`（按 featureKey 判权）、`useImmersive`（全屏）。
- **三后端降级链是硬要求**：WebGPU→WebGL2→Canvas2D 逐级 try/catch + 超时降级，粒子数量按后端/设备分级（量级：WebGPU 数千–2 万、WebGL2 千级、Canvas2D 百级），任何环境不白屏、可玩。
- 实现难度：中高（GPU 渲染核心 + 三款游戏 + 全屏容器），但全部为成熟浏览器 API 且平台已有 GPU 工具（`gpu-data-viz`）与无头验证沉淀（`references/gpu-headless-testing.md`），风险可控。

## 集成成本与侵入性

- **新增（增量）**：mini-games 下新增 `engine/`（渲染抽象与三后端）、`gpu-games/`（3 款 GPU 游戏）、`components/FocusStage.vue`（专注全屏容器）、对应单测与 E2E。
- **改动（受控、少量）**：`mini-games/index.vue`（从"单层面板"改为"选游戏页 + FocusStage 两层"，接入进出场全屏手势）、`manifest.ts`（更新 tagline/keywords、新增炫光权益 features，**billing 主价格与 mode 不动**）。
- **不改**：路由/注册（`import.meta.glob` 自动发现，slug 不变）、`manifest.webmanifest`、Service Worker 缓存策略、现有 4 款游戏内部逻辑、其它 26 个工具。
- 侵入性低：新引擎/GPU 游戏用**动态 `import()` 拆独立 chunk**，不进入主包与 DOM 游戏路径；仅在用户进入 GPU 游戏时按需拉取，老用户与低端机不承担体积/启动成本。

## 架构兼容性

- 不引入重型框架与第三方图形库（**自研零新增 npm 依赖**，与 fangzi 现状一致）；如确需矩阵运算，仅评估 MIT 的 `gl-matrix`，默认自研。
- Service Worker：新 chunk 走 Vite 产物 + 现有 SW 预缓存/运行时缓存规则；需专项验证"首次在线进入后断网仍可打开 GPU 游戏"。
- PWA 可识别性：不改 manifest/注册逻辑/HTTPS；全屏只在工具页内、由用户手势进入、路由离开调用 `useImmersive.exit()`，不影响安装与离线。

## 平台合规评估

- **EdgeOne Pages（纯静态）**：无服务端函数，GPU 引擎/WGSL 为 JS 文本内嵌、音画全部程序化、**无图片/音频/字体/wasm 大素材**，单文件与总体积增量很小，远低于免费版单文件 25 MiB / 项目 5 GiB / 20000 文件限额；不涉及动态服务端，合规。
- 不涉及 Chrome Web Store / IDE 插件商店审核（PWA 内功能），无个人开发者上架资质问题。
- 振动/全屏/音频均在用户手势内请求，音频遵守自动播放策略（首次交互后创建 AudioContext）；提供静音与振动开关，无合规风险。

## 资金成本

零资金：仅浏览器原生能力与现有免费 EdgeOne Pages 托管；无任何需付费的 API/模型/素材；所有自研代码与所用 API 均可商用，不使用非商用（NC）资源。

## 时间成本与开发难度

- 独立开发者、H 档（涉及 WebGPU/WASM 式渲染与多后端降级）。建议拆里程碑：
  - M1：渲染抽象 + WebGL2/Canvas2D 后端 + FocusStage 纯净全屏 + 炫光连消（复用 match3-core）跑通全链路与三端验证（**可独立交付的可运行 checkpoint**）；
  - M2：WebGPU/WGSL 后端（compute 粒子 + Bloom）+ 霓虹脉冲；
  - M3：星轨穿梭 + 主题/色盲/粒子规格设置 + 分享收尾。
- 质量门不降低：纯逻辑内核与降级选择走毫秒级 node:test；视觉按 GPU 无头规范强制 WebGL2 截图（不截无头 WebGPU 上屏）；真机/独显上线前后各肉眼复核一次 WebGPU 上屏。

## 用户真实价值

- 直接价值：碎片时间获得高质感、强正反馈、零干扰的放松；省下载、省广告、离线可玩。
- 对 fangzi 的商业价值：**最直观的技术力"门面"与拉新话题点**（"网页不用装还能这么炫"），提升小游戏模块与整个 PWA 的停留时长、回访与分享；免费炫光款把用户转化为平台信任者，间接带动其它专业工具与专业版整体转化。

## 市场与竞争

- 赛道红（CrazyGames 等 4500+、独立游戏 App 众多），但差异化清晰：零下载零注册零广告零追踪、可离线、WebGPU 画质但包体极小且低端可降级、**游戏中绝对纯净无任何无关信息**、与工具箱生态互导流。不与 3A/重度游戏竞争，主打"几分钟、干净、爽"。

## 盈利方式建议

- 沿用 `mini-games` 现有 **freemium**，**不改主价格与 mode**（保守、不影响已购用户与既有结算）：
  - 免费层：现有 2048/记忆翻牌 + **新增 1 款炫光游戏（建议"炫光连消"）免费**，让所有用户直接体验 GPU 画质（引流/惊艳）；
  - 专业版（既有买断，权益扩充）：解锁霓虹脉冲、星轨穿梭、炫光游戏进阶难度/全部霓虹主题皮肤/更高粒子规格/色盲模式，同时包含原有华容道、三消；**已购专业版用户免费获得全部新增内容**（增强获得感、减少争议）。
  - 在 `manifest.billing.features` 中新增炫光相关权益条目，用 `useToolBilling.canUse(featureKey)` 判权；付费墙与下单复用现有组件。
- 是否进一步下调价格：记录为"可选、需用户确认"，本轮**不擅自改动已上架价格**（遵循保守执行）。

## 结论与依据

**可集成（重构升级原功能 `mini-games`）。** 依据：① 需求真实、被用户明确强调且技术时机成熟；② 与现有小游戏合集大品类重复但有"GPU 炫酷渲染 + 游戏内绝对纯净全屏"两个明确新区别，按规范应整合升级而非新开并列工具；③ 全部为浏览器原生能力、零新增依赖、零资金、可商用、无 NC 资源；④ 动态 chunk + 三后端降级使侵入性与体积可控，不破坏 SW/manifest/路由及其它工具；⑤ 存量最高分与设置可零迁移安全共存；⑥ EdgeOne 静态与限额合规。进入架构师阶段设计 WebGPU/WebGL2/Canvas2D 渲染抽象、FocusStage 全屏容器、三款 GPU 游戏与按需加载方案。
