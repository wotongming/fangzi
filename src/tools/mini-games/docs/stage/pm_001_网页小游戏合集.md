# PM 评估报告：轻量网页小游戏合集（打发碎片化时间）

- 对应 innovator：innovator_001_网页小游戏合集.md
- 评估日期：2026-10-17
- 结论：**可集成（新增）**

## 与 fangzi 现有功能去重与整合判定

对照 fangzi README「内置工具清单」与 `src/tools/` 目录（共 19 个工具：年终奖个税筹划器、离职补偿金、加班费、正则测试、JSON 格式化、批量文本处理、时间戳转换、图片转换、文件哈希、密码生成、居家健身、简历 JD 匹配、本地知识库、本地转写、工资条/个税类、嵌入组件生成、GPU 数据可视化、跨框架组件、方子伴读等）：

- 现有功能均为**效率/合规/工具类**，**无任何娱乐/游戏类功能** → 判定**不重复**，按常规流程评估是否可集成。
- 备注：与「居家健身摄像头」「本地知识库」等偏内容/体验类工具形态不冲突，游戏为全新场景。

## 需求真伪判断

- **真实需求**：用户（佟明账号）于 2026-10-16 与 2026-10-17 连续三次来信，诉求稳定一致（打发碎片化时间、没有小游戏、希望不断开发网页游戏），非一次性随口提议；符合真实使用频次验证。
- **对 fangzi 用户群的匹配度**：方子用户以上班族/学生/家庭为主，碎片时间娱乐需求普遍；与「单点工具、口语化搜索」的使用习惯契合（用户搜索词即「小游戏/打发时间」类）。
- **注意点**：娱乐功能与效率工具定位有张力，需在产品形态上保持「轻量、不打扰」，作为留存/活跃增强而非主打变现，方向成立。

## 技术可行性

- 纯前端 Canvas 2D + requestAnimationFrame 即可实现 2048/翻牌/华容道/消消乐/数独等，**无需后端、无需第三方游戏引擎**（不引入 Phaser 等重型依赖，控制包体）。
- 方子技术栈：Vue 3.5 + TypeScript + Vite 8 + Pinia + vue-router，PWA 由 vite-plugin-pwa/Workbox 托管；游戏作为新工具目录（manifest + Vue 组件）接入，完全符合现有工具框架。
- 离线能力：游戏资源小，可纳入 Service Worker 预缓存；本地进度用 IndexedDB。
- 风险：EdgeOne Pages 静态托管有 25MiB 资源上限（项目已有 postbuild 校验先例），需控制单款游戏资源体积（程序化绘制、压缩素材），**可行且已有应对惯例**。

## 集成成本与侵入性

- **零核心改动**：fangzi 工具框架设计为「新增一个工具只需新增一个目录、填一份 manifest，零核心改动、零路由改动、零检索改动」，游戏工具走同一通道。
- Service Worker / manifest / 现有路由：不动；新工具由构建自动纳入预缓存与检索索引。
- 存量功能不受影响：新增目录与现有 19 个工具完全隔离。

## 架构兼容性

- Vue3 组件 + Canvas，复用现有样式体系（原生 CSS，无 UI 库）；状态可用 Pinia；本地存储用 IndexedDB（与现有 household-finance、local-knowledge-base 等工具一致）。
- 符合「无自研后端、纯前端 + 浏览器本地能力」的硬约束；不引入重型框架，不破坏 PWA 可识别性（manifest/SW/HTTPS 均不动）。

## 平台合规评估

- **EdgeOne Pages**：静态托管，游戏为纯前端静态资源，无动态服务端函数，符合平台政策；需控制单包体积（25MiB）。
- 内容合规：游戏须避开赌博（含模拟博彩）、色情、暴力血腥、诱导消费等红线内容；益智类小游戏无合规风险。
- 无插件商店分发环节（PWA 内嵌），不涉及 Chrome Web Store 等商店政策。

## 资金成本

- 零成本：无后端、无第三方付费 API、无游戏引擎授权费；素材采用程序化绘制/免费可商用资源（禁止非商用授权素材，规避版权风险）。
- 会员计费复用 fangzi 现有「内置计费能力」（免费/买断/Freemium/按次四模式，网页工具与插件统一接入），无需新增支付设施。

## 时间成本与开发难度

- 复杂度：中低。首批 3–5 款经典益智小游戏（2048、翻牌、华容道、消消乐、数独），单款 2–4 天，框架与集成 2–3 天，合计约 2–3 周（独立开发者）。
- 均为成熟玩法，逻辑可复用，无算法研究风险。

## 用户真实价值

- 核心痛点：碎片时间无聊、缺轻量娱乐 → 情感/精神价值（放松、成就感）。
- 使用频次：碎片场景每天多次，高于多数效率工具；可显著提升回访与停留时长。
- 对 fangzi 的价值：补齐娱乐场景，工具集合覆盖「效率 + 生活 + 娱乐」，增强留存与会员价值感知。

## 市场与竞争

- 单机小游戏市场整体红海，但本功能定位为方子工具集合内的**附属留存功能**，不独立获客、不与主流游戏 App 正面竞争。
- 差异化：随搜随玩、离线轻量、无广告、与效率工具同一 PWA 入口；对已有 fangzi 用户是零迁移成本的新场景。

## 盈利方式建议

- **Freemium**：基础款免费；会员解锁完整游戏库 / 去广告 / 主题皮肤。
- 复用 fangzi 现有计费框架，不单独建支付链路；广告变现不作为优先项（保持轻量、不打扰的产品调性）。

## 结论与依据

- **结论：可集成（新增）**。
- 依据：① 需求真实且多次来信佐证；② 技术完全可行（纯前端 Canvas，符合无后端 PWA 约束与 EdgeOne 限制）；③ 集成成本低（工具框架零核心改动）；④ 与现有功能不重复、无合规红线；⑤ 零资金成本，可作为留存/活跃增强功能，与方子产品调性兼容。
