# 部署运维指引：可嵌入交互组件生成平台

- 对应 architect：architect_006_可嵌入交互组件生成平台.md
- 编写日期：2026-10-15

## 部署架构与环境准备

- 部署架构：EdgeOne Pages 静态托管：①fangzi 内的生成器工具页（dist/）；②生成的组件脚本（public/widgets/ 静态资源，版本化 URL 分发）；数据回流默认本地（IndexedDB），可选自有端点。
- 环境清单：Node ≥ 20.19（构建机）；EdgeOne Pages 账号（已有）；可选：自有数据收集端点（如 EdgeOne Functions 免费额度或第三方免费表单后端，需商用友好）。

## 软硬件配置清单

| 项 | 规格 |
| --- | --- |
| 构建机 | Node 20+ |
| 部署 | EdgeOne Pages（免费额度，承载生成器与组件脚本） |
| 客户端 | 现代浏览器（生成器）；宿主站点任意技术栈（组件脚本） |
| 数据 | 默认本地；可选自有端点 |

## 部署步骤

1. `cd fangzi && npm install && npm run build`
2. EdgeOne Pages CLI/Git 推送 dist/（含 public/widgets/ 组件脚本目录）
3. 验证：生成组件 → 复制嵌入代码 → 独立 HTML 实测 → 数据导出正常
4. 更新 README 工具清单（登记 embed-widget-builder 七字段）

## 配置项说明

- 可选环境变量：`VITE_WIDGET_ENDPOINT`（提交数据收集端点；未配置则本地存储，隐私可控；参照现有 VITE_FEEDBACK_ENDPOINT 模式）；组件脚本版本号在 lib/snippet.ts 与构建输出约定。

## 上线/灰度方案

- 内部灰度（表单/计算器模板）→ 观察生成与嵌入成功率 → 全量；组件脚本版本化发布，旧嵌入实例不受影响。

## 平台对接指南

- **EdgeOne Pages**：个人账号即可；部署 CLI/Git；HTTPS 平台提供；版本更新=重新部署（组件脚本 URL 带版本号，宿主可锁定版本）。
- **可选数据端点**：若需在线收集提交数据，可选用 EdgeOne 免费额度内的静态/函数能力或商用友好的免费后端（如 neon 免费 postgres + 轻量接口，注意免费额度条款商用友好）；未配置时功能完整可用（本地），故此项非依赖。
- 其余平台（Chrome Web Store 等）：不涉及。

## 运维监控指标与告警

- 指标：生成器访问量、组件脚本加载失败率（宿主侧可选上报）、嵌入实例数（本地统计）；
- 告警：组件脚本 404 → 检查 widgets/ 目录版本文件是否随部署发布。

## 日志管理

- 生成器 console + error 聚合；不采集宿主站点数据（默认本地）。

## 备份与容灾

- 用户组件配置与数据默认在本地 IndexedDB；无服务端数据；代码仓 git 备份；可选端点模式下数据在自有后端（按该后端备份策略）。

## 常见故障排查与回滚预案

- 组件脚本加载失败：检查版本 URL 与 CSP（宿主需允许脚本加载，文档提示）；确认 widgets/ 已发布；
- 数据未收集：检查是否配置 VITE_WIDGET_ENDPOINT 且 CORS 允许；
- 严重问题：`git revert` + 重部署；组件脚本版本化保证已嵌入站点不受回滚影响。
