# PM 评审 · 006 求职管线与简历穿透

**结论：可集成（重构升级 resume-jd-matcher），本轮不编码，待点名。**

## 去重判定
resume-jd-matcher 已覆盖：简历 PDF/DOCX 本地解析、JD 关键词匹配分、硬门槛核对、可溯源改写建议、求职信、投递看板与跟进。006 的"投递台账/跟进提醒"与现有看板重合。

但 006 提出一个现有工具未做的真新痛点：**ATS 本地穿透体检**——模拟招聘系统机器解析：两栏/图片/表格导致文本乱码或判空、联系方式是否被正确提取、关键词密度。这与现有"JD 匹配"不同，是"简历自身能否被机器读懂"。

## 整合方案（重构，不新开并列工具）
- 复用 resume-jd-matcher 入口/目录 `src/tools/resume-jd-matcher/`、IDB `fz-resume-jd-v1`、PDF/DOCX 解析链路。
- 新增 `lib/ats-check.ts`：对已解析文本做结构性体检——
  - 检测是否多栏（pdf.js 文本块 x 坐标分布）、是否含图片型简历（提取文本过短但页数>0）；
  - 联系方式正则（手机/邮箱/LinkedIn）是否命中；
  - JD 关键词密度与覆盖。
- 在投递看板上补"转化率漏斗"（投递→回复→面试→offer）。
- **存量兼容**：IDB 既有投递记录结构不变，新增 atsScore/funnel 字段可选；不丢历史投递。

## 风险
ATS 真实各家解析器不同，本地结果仅作"格式健康参考"，需在 UI 明示不保证过筛。
