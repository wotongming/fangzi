# PM 评估报告：账单订阅盘点与自动续费本地预警

- 对应 innovator：innovator_009_账单订阅盘点自动续费预警.md
- 评估日期：2026-10-17
- 结论：**可集成（新增独立工具，本轮次优先候选，排在 006 之后）**；建议档位 M

## 与 fangzi 现有功能去重与整合判定
与 `household-finance`（家庭财务管家）有"都和钱/微信支付宝有关"的表层重叠，经核代码：它是**逐笔手工记账 + 预算 + 报表 + 洞察**，导入导出仅为**自家 JSON 加密备份/恢复**（`accept=".json,.txt"`），**不能解析微信/支付宝官方账单 CSV，也没有周期性订阅识别、闲置/涨价判定、解约指引、续费预警**。二者目标与交互不同（一个是长期手动记账，一个是"一次性导入账单自动盘点订阅、省钱退订"）。
**结论：判定不重复（新场景），新增独立工具 `subscription-audit`**。可在报告层与 household-finance 互链（"想长期记账→家庭财务管家"），但不并入，以免让轻量的一次性省钱工具背上记账门槛、也不改动其存量账本数据结构。

## 需求真伪判断
真实、省钱结果可量化。媒体与市场监管反复提示自动续费乱象：分散在微信/支付宝两入口、难自查，"首月1元"忘关，用户自查常发现一年白交上千元，平均每人每月白交 50–100 元（央广网、澎湃、石家庄市场监管局、抖音多个自查教程）。

## 技术可行性
纯前端可行且不碰账户：
- 用户按指引从微信/支付宝官方导出账单 CSV，本地解析（多编码 GBK/UTF-8、表头/汇总行清洗；自研轻量 CSV 解析或引入 MIT 库）。
- 订阅识别：同一商户按近似金额 + 近似周期（月/季/年）聚类，输出名称/周期/单价/最近与预测下次扣费/累计；用规则+阈值，允许用户纠正。
- 标注疑似闲置、重复同类会员、涨价；计算一年/三年累计与"取消可省"；解约给微信/支付宝官方路径与直达链接。
- 待办与下次扣费提醒：Notification + `.ics`（可与 004/008 复用"计划调度+ics"模块）。报告导出 CSV/打印。
- 关键难点是两平台 CSV 字段/格式随版本变化——做成"字段映射可配置 + 容错 + 只取收支明细行"，并内置导出步骤指引，不承诺自动登录抓取（无后端也做不到，反而更安全）。

## 集成成本与侵入性
新增独立工具目录，零核心改动；CSV 解析、周期聚类可沉淀 reusable-module。低到中侵入。

## 架构兼容性
无后端、纯本地解析，契合静态 PWA；大账单用 Worker（worker-post）避免卡顿。

## 平台合规评估
PWA 无资质障碍；不碰支付账号、不自动解约（只给官方入口与指引），规避金融/支付合规风险；财务数据不出设备是强信任卖点。

## 资金成本
零成本、零外部数据服务。

## 时间成本与开发难度
中（M）：两平台账单解析容错、周期聚类算法、提醒与报告；需以脱敏样例回归（可用自造多份账单 CSV 单测）。单轮可交付。

## 用户真实价值
直接省钱（常见数百至上千元/年）、ROI 直观、易传播；对转化拉动明显。

## 市场与竞争
平台只给解约入口，不做跨平台聚合与成本分析；通用记账要长期手填门槛高。一次性导入账单自动盘点订阅、本地隐私的轻量工具空白明显。

## 盈利方式建议
freemium（单份账单/基础订阅识别免费）＋买断/订阅（多月多账户合并、年度趋势、闲置/涨价智能判定、扣费提醒与退订待办、报告导出）。

## 存量数据与配置保护
全新工具，不改 household-finance 任何账本/预算数据；仅互链，回归其现有功能确认无影响。

## 结论与依据
可集成、纯前端、零资金、单轮可交付、省钱价值直接；本轮在 006（照片隐私）之后作为次优先，**可纳入本轮或紧邻下一轮**。
