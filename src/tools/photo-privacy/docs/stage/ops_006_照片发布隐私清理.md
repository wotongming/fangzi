# 部署运维指引：照片发布前本地隐私清理与脱敏工作台（photo-privacy）

- 对应 architect：architect_006_照片发布隐私清理.md
- 编写日期：2026-10-17

## 部署架构与环境准备
纯静态 PWA 内网页工具，无后端、无数据库、无环境变量、无外部 API。构建产物随 fangzi 主站静态托管于腾讯云 EdgeOne Pages，随 main 分支推送自动构建发布。离线能力由现有 Service Worker 统一管理，本工具不改动 SW。

## 软硬件配置清单
无服务器/无容器。客户端要求：支持 Canvas/createImageBitmap 的现代浏览器（Chrome/Edge/Firefox/Safari 近年版本）；批量加速需 OffscreenCanvas（不支持时自动降级主线程）。

## 部署步骤
1. 代码合入 main（本次随流水线提交推送到 `git@gitcode.com:m0_45688211/fangzi.git` 的 main）。
2. EdgeOne Pages 关联仓库自动 `npm ci && npm run build`，发布 `dist/`。
3. 本地权威验证：`npm run build` 后 `npx vite preview --port 4173 --host 127.0.0.1`，跑三视口 E2E。
无需单独发布流程或人工配置。

## 配置项说明
无密钥/无环境变量。计费默认走 LocalMockProvider（未配置 `VITE_BILLING_ENDPOINT` 时开箱即用）；将来接入真实支付只需配置该变量，工具代码不改。

## 上线/灰度方案
纯新增目录、不改存量，可直接全量。如需灰度，可短期在 manifest 用 `status:'beta'` 或在工具集做入口控制；确认稳定后转 stable。

## 平台对接指南
- **EdgeOne Pages**：沿用站点既有项目与自定义域名 https://www.fangzi.asia 、HTTPS 证书、自动部署；本工具无新增资源服务，不需要额外配置。遵守免费版限额：单项目 ≤5GiB、文件数 ≤20000、单文件 ≤25MiB（本工具仅小幅 JS/无大资源，远低于限额）。
- 无浏览器插件/IDE 插件分发，不涉及各插件商店。

## 运维监控指标与告警
静态资源无自建监控。关注：构建是否成功（EdgeOne 构建状态）、前端 `window.onerror`/线上反馈邮箱 fangziasia@163.com 中关于本工具的报错（某浏览器不支持 OffscreenCanvas/toBlob/webp、EXIF 解析异常）。无服务端指标。

## 日志管理
无服务端日志。用户图片全程本地、不上传、不持久化（仅内存对象 URL，离开释放）；仅计费走既有框架（默认本地 mock，不涉及图片内容）。

## 备份与容灾
代码在 GitCode 仓库为唯一事实源，可随时重建；静态站由 EdgeOne 多节点承载。用户数据在其本机 IndexedDB（仅偏好设置，非图片），清除站点数据即重置，无服务端备份需求。

## 常见故障排查与回滚预案
- 某浏览器批量卡住/报 OffscreenCanvas 错：已内置主线程降级；若仍异常，单张处理（非 Worker）路径不受影响。
- 输出方向错乱：createImageBitmap 的 imageOrientation 在个别老浏览器不生效 → 回退按 exif.orientation 手动变换（在 process.ts 预留）。
- webp 编码失败（旧 Safari）：自动回退 image/jpeg。
- EXIF 解析误报：解析纯函数带 try/catch，失败仅不展示元数据，不阻断"重绘剥离"（重绘本身无条件去元数据）。
- **快速回滚**：本功能为纯新增目录，不影响主体。紧急下线：`git rm -r src/tools/photo-privacy` 后推送（或 revert 对应提交），主站与其它工具不受影响；不涉及数据迁移。
