# PM 评估报告：跨框架组件库工作台

- 对应 innovator：innovator_005_跨框架组件库工作台.md
- 评估日期：2026-10-15
- 结论：**可集成（新增）**

## 与 fangzi 现有功能去重与整合判定

对照 fangzi README 与 `src/tools/`：现有工具无组件生成/代码脚手架类功能（fangzi 的 `new:tool` 脚手架是仓库内开发脚本，面向 fangzi 自身的工具扩展，不是面向用户的组件生成产品；正则/JSON 等是单点工具）。innovator_005 是面向「前端开发者构建跨框架 Web Components 组件库」的浏览器工作台，对象与场景完全不同。

- **判定不重复** → 新增独立工具。

## 需求真伪判断

- 真需求。证据链：Web Components 2026 全面回归（98.7% 浏览器支持、78% 企业评估/采用）；大厂（GitHub Primer、Adobe Spectrum、SAP UI5、ING Lion、Salesforce LWC）因「多框架需维护多套组件库」的重复开发痛苦而采用 WC；社区明确抱怨 WC 生态「无主导工具链、tree-shaking 失效、DX 样板代码多、无文档/脚手架工具」（dev.to《Web components failed. We can fix them.》）。
- 使用频次：组件库持续迭代=项目期高频使用；与 fangzi 用户群匹配：fangzi 已有开发者工具品类（正则/JSON/时间戳/哈希），开发者是核心用户之一，新增「组件开发」工具强化开发者生态。

## 技术可行性

- 完全可行，纯前端实现：
  - 可视化建模：Vue 表单驱动组件属性/事件/插槽/CSS 变量定义；
  - 代码生成：模板字符串生成 Lit（约 5-6KB）或原生 Web Components + TypeScript 骨架；跨框架 wrapper 按模板生成（React/Vue/Angular 适配代码）；
  - 预览：Shadow DOM iframe 沙箱内实时渲染，属性面板实时改值；
  - 文档/Manifest：由定义数据自动生成 API 文档、演示页、custom-elements.json；
  - 导出：fflate（MIT）打包单文件脚本或 npm 包结构 zip。
- 技术风险：代码生成器边界（复杂组件仍需手写，定位为「骨架+可编辑」而非全自动）；预览沙箱 CSP 兼容。

## 集成成本与侵入性

- 新增 `src/tools/wc-workbench/`，工具框架自动发现，零核心/路由改动；
- 不触碰 SW/manifest；编辑器轻量方案（CodeMirror MIT 或 textarea+高亮），避免 Monaco 重型依赖；
- 存量影响：无（纯新增）。

## 架构兼容性

- 与 fangzi 零后端纯前端架构兼容；产物本身就是浏览器原生组件，与 PWA 技术栈同构；
- 不引入 UI 框架，符合开发规范。

## 平台合规评估

- EdgeOne Pages：静态托管，无服务端需求；部署包增量小，合规；
- 不进插件商店（工具不发布到 Chrome Web Store，仅在浏览器内生成代码供用户自行分发），无商店政策问题；内容合规无风险。

## 资金成本

- 零成本可行：Lit（BSD-3）、CodeMirror（MIT）、fflate（MIT）；无任何付费服务依赖，全部商用友好授权。

## 时间成本与开发难度

- 复杂度：中（表单建模 + 模板生成 + iframe 预览）；
- 独立开发者估算：建模与表单 2-3 天、代码生成器 3-4 天、预览沙箱 2 天、文档/Manifest/导出 2 天、回归 1-2 天，合计约 10-13 人日。

## 用户真实价值

- 核心痛点：跨框架组件重复实现（一套组件三套维护）；WC 原生 API 繁琐、无脚手架/文档工具；
- 使用频次：组件库开发期高频；对 fangzi 价值：强化开发者品类、扩大专业用户群，Pro 协作付费空间（对标 Storybook Pro）。

## 市场与竞争

- 竞品：Storybook（偏框架组件、无 WC 一体化生成）、Bit/Builder.io 类（贵、偏企业）、无 WC 专用一体化工作台；
- 差异化：免费 + 浏览器免安装 + WC 全生命周期（建模→生成→预览→文档→发布）+ 工具集合生态。

## 盈利方式建议

- freemium：免费（基础生成、公开模板）；Pro（buyout ¥49.90 或订阅）解锁跨框架 wrapper 批量生成、私有组件库、团队协作、自定义模板。

## 结论与依据

- **可集成（新增）**：与现有功能无重复；纯前端零资金可行、不破坏存量、平台合规；WC 生态 2026 年爆发但一体化工具缺口明确，付费空间来自省重复实现人力（企业级强需求）。
