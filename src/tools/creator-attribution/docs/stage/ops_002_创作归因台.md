# 部署运维指引：独立创作者跨平台内容复盘与收益归因台（creator-attribution）

- 对应 architect：architect_002_创作归因台.md
- 编写日期：2026-10-20

## 部署架构与环境准备

本功能为 fangzi PWA 新增的一个纯前端工具页，无后端、无独立服务、无插件商店：

```
开发者 git push main
  └─> EdgeOne Pages 自动构建（npm ci && npm run build）
       └─> 静态 dist/ CDN 全球 HTTPS 分发
            └─> 浏览器 SW 预缓存新 chunk -> 离线可用
                 └─> IndexedDB fangzi-creator-attribution v1 首次打开建四表
```

环境准备：EdgeOne Pages 已关联 GitCode `fangzi` main 分支（既有流水线）。

## 软硬件配置清单

| 项 | 规格 | 说明 |
| --- | --- | --- |
| 托管 | EdgeOne Pages 免费版 | 静态、可商用免费额度 |
| 构建 | `npm ci && npm run build` | 既有 |

| 限额核查 | ≤5GiB / ≤20000 文件 / 单文件 ≤25MiB | 本工具增量 80–150KB gz、零大资产，合规 |

## 部署步骤

1. 本地质量门全过：`npm test` → `npx vue-tsc --noEmit` → `npm run verify:tools` → `npm run build`。
2. `git add src/tools/creator-attribution/ test/creator-attribution.test.ts README.md` → commit（`feat: 新增创作者内容归因台`）→ `git push origin main`。
3. EdgeOne 自动构建（1–3 分钟），控制台确认成功。
4. 线上打开 `/#/t/creator-attribution` 冒烟：建账号→录台账→看板→CSV 导入→月报导出。
5. 老用户：SW 后台更新，下次刷新生效；IndexedDB 新库首次打开即建。

## 配置项说明

- 无新增环境变量。沿用 `VITE_BASE` / `VITE_BILLING_ENDPOINT`（未配走 LocalMock 本机演示支付）/ `VITE_FEEDBACK_ENDPOINT`。
- 计费配置在 `manifest.ts`：`priceCents: 1990`（¥19.90 买断）+ 5 个 feature key；改价改此值即可。

## 上线/灰度方案

- 静态单站无逐用户灰度，随版全量发布。
- 上线后 24h 人工抽查三视口与 CSV 导入（UTF-8/GBK 各一）；阻断问题立即回滚。
- 回滚触发条件：新工具页白屏/报错导致整站异常、SW 预缓存新 chunk 失败、归因聚合数值明显错误。

## 平台对接指南

- **EdgeOne Pages**：注册/绑库/HTTPS 证书均既有配置，本次仅 push main；版本更新=重新构建；回滚=revert 后 push。
- **Chrome Web Store / VS Code / JetBrains**：本工具为 PWA 内页，**不涉及任何插件商店，无对接步骤**。
- **抖音/小红书/B站/公众号等平台开放 API**：**刻意不对接**——小创作者无企业资质、且规避平台合规风险；数据来源仅本地手动录入与 CSV 导入，文档中需向用户说明"本工具不抓取、不登录、不读取你任何平台账号"。
- **支付平台**：不直接对接，统一走 fangzi 计费 Provider。

## 运维监控指标与告警

- EdgeOne 构建状态告警（控制台自带）；线上工具页可用性人工/外部拨测。
- 纯本地计算无服务端错误面；风险在用户端 DB 建库与 CSV 解析，代码内已 try/catch 降级。

## 日志管理

- 无服务端日志。用户端异常在界面 `.err` 提示，引导经既有反馈邮箱 `fangziasia@163.com` 反馈。

## 备份与容灾（纯前端本地数据）

- 数据全在用户浏览器 IndexedDB `fangzi-creator-attribution`，服务端无备份义务。
- 工具内提供备份出口：①月度经营报告 Markdown 导出；②台账/商单 CSV 导出（`export.ts`）。guide 须明确提示"重要数据定期导出 CSV/MD 备份；清浏览器站点数据会清空本机记录"。
- 换机迁移路径：旧机导出 CSV →新机导入（导入为追加模式）。

## 常见故障排查与回滚预案

| 故障 | 排查 | 处理 |
| --- | --- | --- |
| 新工具页白屏 | Console 是否新 chunk/建库异常 | 代码已 try/catch；若仍崩 → 回滚 |
| CSV 导入乱码 | 是否 GBK 文件（decodeText 已回退） | 预览阶段暴露乱码则不入库；人工另存 UTF-8 再导 |
| CSV 列识别错 | findColumn 未命中中文列名 | 预览提示缺列，引导用户改列头或选模板列 |
| 看板数值不对 | 工时为 0 导致 ROI 回退（设计如此） | 确认是设计行为而非 bug |
| 付费权益丢失 | 计费订单存储 | 本机 LocalMock / 远端权益，按 `VITE_BILLING_ENDPOINT` 判定 |

**出问题如何快速撤下而不影响 fangzi 主体**：
1. `git revert` 上一个 main commit → push，EdgeOne 重发旧版。
2. 本工具为**全新独立目录 `src/tools/creator-attribution/` + 全新 IndexedDB 库**，回滚后：①其余 27 工具、首页检索、计费框架零改动；②该新库数据留在用户浏览器但不再被访问，无副作用、无需清理。
3. 如暂不想整站回滚而只想下线本工具，可从 `src/tools/` 移除该目录（registry 自动发现会随之去掉入口），再发一版——比 revert 更细粒度。
